# editor-presets — Delta

## ADDED Requirements

### Requirement: Preset configuration scope

A preset SHALL capture a named snapshot of all user-changeable editor parameters: grid type,
canvas size, sub-cell detail, palette, render mode, pixel style, metaball settings, connectivity,
background, connector width and symmetry. A preset SHALL NOT contain painted content (cells,
links). Stored configs SHALL be validated and clamped to the same ranges as the document
deserializer on both read and write.

#### Scenario: Snapshot covers every parameter

- **WHEN** the user saves the current settings as a preset and applies it later
- **THEN** grid type, canvas size, sub-cells, palette, render mode, pixel style, metaball
  settings, connectivity, background, connector width and symmetry all match the saved values

### Requirement: Built-in presets

The editor SHALL ship a read-only set of built-in presets (at least 5, at most 10) with
configurations tuned for attractive output. Built-ins SHALL be listed together with user presets,
marked as built-in, SHALL NOT be renamable, overwritable or deletable, and SHALL be duplicable
into editable user presets.

#### Scenario: Built-ins survive storage loss

- **WHEN** IndexedDB is unavailable or the presets store is empty
- **THEN** the built-in presets remain listed and applicable

### Requirement: Applying a preset

Applying a preset SHALL be a single undoable document transition that preserves painted content:
grid type and size changes go through the existing content-preserving conversion path, sub-cell
changes resample, and palette changes recolor cell values in place. The symmetry state SHALL be
set from the preset (symmetry changes remain outside undo history). The editor SHALL highlight
the preset whose configuration currently matches the document exactly.

#### Scenario: Apply recolors and resizes without erasing

- **WHEN** the user applies a preset to a canvas with painted cells and presses undo
- **THEN** the document returns to the previous configuration with content intact

### Requirement: Preset storage

The editor SHALL persist user presets in IndexedDB (database `glyph-editor`, store `presets`,
schema version 2 with a shared DB opener for both stores), each entry containing a unique id,
name, creation and update timestamps and the validated preset config. When IndexedDB is
unavailable the store SHALL degrade to an in-memory fallback with the same API.

#### Scenario: Preset survives reload

- **WHEN** the user creates a preset and reloads the editor
- **THEN** the preset is still listed and applies to the same configuration

### Requirement: Presets panel section and manage dialog

The editor SHALL provide a collapsible Presets section in the settings panel listing all presets
with a generated style preview, applying on click and highlighting the active one, plus a Manage
action. The Presets dialog SHALL allow saving the current settings under a user-provided name and
list all presets as cards (generated preview, name, config summary, badges) with actions apply,
duplicate, overwrite-with-current-settings (user presets), inline rename (user presets) and
delete with inline confirmation (user presets).

#### Scenario: Full CRUD round trip

- **WHEN** the user saves the current settings as "Night", applies a built-in, overwrites the
  built-in's duplicate "Night copy" with new settings, renames it and deletes it
- **THEN** each operation is reflected immediately in the list and the store

### Requirement: Preset previews

Preset lists SHALL show a preview image generated by rendering a deterministic procedural sample
artwork through the preset's configuration. Previews SHALL NOT be persisted.

#### Scenario: Preview reflects the look

- **WHEN** a metaball preset and a chamfer pixels preset are listed
- **THEN** their previews visibly differ according to each preset's render mode and styling

### Requirement: Localization

All preset-related user-facing strings SHALL be available in English and Russian.
