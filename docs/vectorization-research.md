# Ресёрч: растрово-векторная трассировка (vtracer V1 и вокруг неё)

Зачем этот документ: в редакторе появляется второй режим «Вектор» — трассировка
изображений в SVG по образцу vtracer V1, с прицелом на гибриды с дизерингом.
Здесь зафиксированы: пайплайн V1, состояние экосистемы, научные источники,
дизайн гибридных сценариев A/B и решения по архитектуре. Документ живой —
обновляется по мере реализации.

## 1. Пайплайн vtracer V1 (эталон, MIT, Rust)

Полностью линейный конвейер (в отличие от potrace, глобально оптимизирующего полигон):

1. **Иерархическая агломеративная кластеризация цвета** (`color_clusters::Runner`) —
   не k-means: листья — прогоны одинаковых пикселей, слияние пар с минимальной
   дистанцией цвета в куче. Управление: `color_precision` (значащие биты/канал —
   квантование перед слиянием) и `layer_difference` (порог дистанции, до которого
   пары сливаются). Результат — merge-дерево, «срез» по порогу даёт слои.
2. **Бинарный слой на кластер**: маска пикселей кластера (+ дыры — отдельные
   компоненты). Контуры обходятся boundary-following'ом с **turning policy**
   (разрешение неоднозначных диагональных стыков), дыры — вложенные контуры
   (иерархия в духе Suzuki–Abe).
3. **Упрощение полигонов**: «лестнично-симметричный» Ramer–Douglas–Peucker
   (симметрия нужна, чтобы диагональные «лестницы» упрощались согласованно в обе
   стороны); порог — `length_threshold`.
4. **Аппроксимация кривыми**: детект углов (`corner_threshold`) → между углами
   least-squares фит кубических Безье по Шнайдеру (Graphics Gems FitCurves:
   chord-length параметризация, Ньютон-репараметризация, ограничение
   `max_iterations`), разброски по превышению ошибки, склейка гладких сегментов
   (`splice_threshold`).
5. **Композиция**: `stacked` — слои красятся друг поверх друга (дыры «просвечивают»
   на нижние слои; устойчиво к швам, но нижние пути содержат скрытые области);
   `cutout` — каждый видимый регион входит ровно в один путь (проще редактировать,
   но на границах возможны волосяные швы антиалиасинга).
6. **SVG-врайтер**: сложные пути fill-rule evenodd (дыры — подпути), точность
   координат `path_precision`.

Параметры V1 (дефолты 0.6.x): `colormode` color|binary; `hierarchical`
stacked|cutout; `mode` spline|polygon|none; `filter_speckle` 4; `color_precision`
6; `layer_difference` 16; `corner_threshold` 60°; `length_threshold` 4.0;
`max_iterations` 10; `splice_threshold` 45°; `path_precision` 8.

V2 (1.0.0-alpha, 2026) — то же ядро, переписанное в конвейер подключаемых стадий,
плюс: watershed-кластеризация, seam-free «mosaic» cutout (общее ребро смежных
регионов фиттится один раз — нет швов), Bradley–Roth адаптивный порог, фиксированные
палитры (OKLab-подбор), paper.js-style повторное упрощение кривых.

## 2. Экосистема и доступность

- Официальный npm `@visioncortex/vtracer` — wasm, но существуют только версии
  **1.0.0-alpha.\*** (V2); V1 (0.6.x) на npm **не опубликован**. Сборка под Node
  (`--target nodejs`), поэтому: в vitest работает как есть (эталон в тестах), в
  браузер без пересборки не годится.
- Rust-тулчейн для собственного wasm не привлекаем: V1 портируется в TS честно
  (объём ядра — кластеризация + трассировка + фиттер — порядка пары тысяч строк).
- Для ручной сверки с «настоящим» V1: веб-демо visioncortex, CLI `vtracer-cli`
  (cargo), Python `vtracer==0.6.x` (PyPI).

## 3. Родственные методы и литература

| Метод/источник | Суть | Роль у нас |
|---|---|---|
| **Potrace** (Selinger 2003, статья свободна; код GPL — не линкуем) | трассировка → полигон → углы → глобальная оптимизация кривых | канон поворота ambiguous-вершин и corner-обработки |
| **imagetracerjs** (public domain, JS) | квантование → слои → edge-nodes (вариант marching squares) → pathscan → divide&conquer фит (линия → квадратичная) | референс простого JS-пайплайна; у нас фиттер сильнее (кубики Шнайдера) |
| **Suzuki–Abe 1985** (findContours OpenCV) | border following + вектор иерархии контуров | дыры/«без дырок» (holes: keep/fill) |
| **Marching squares** (+ d3-contour) | контуры уровня по 2×2 | уже есть в проекте (metaball/outline) |
| **RDP / Visvalingam–Whyatt** | упрощение полилиний | RDP — паритет с V1; VW — опция эстетики |
| **Schneider FitCurves** (Graphics Gems; JS-порт `fit-curve`) | error-bounded least-squares кубики | фиттер обоих трассеров (outline + centerline) |
| **Zhang–Suen 1984 / Guo–Hall 1989** | thinning (скелетизация) | centerline-режим для лайнарта |
| **SLIC superpixels** (TPAMI 2012) | k-means в labxy | не нужно для V1; кандидат на «регионную» сегментацию фото |
| **Im2Vec / LIVE / Deep Vectorization** (CVPR'21/22, TPAMI) | ML-векторизация через дифференцируемый растеризатор | вне скоупа: минуты GPU на картинку; обзор — arXiv 2306.06441 |

Вывод: для браузера и для нашей интеграции классический пайплайн — правильный
инструмент; ML-подходы оставлены как контекст.

## 4. Расширения относительно «голого» V1 (в скоупе фазы 1)

- **holes: keep | fill** («без дырок») — keep = паритет V1 (evenodd-подпути);
  fill = вложенные контуры (дети Suzuki–Abe) пропускаются, область заливается
  целиком. Для многих задач (и для последующего наложения текстур) с «дырками»
  работать неудобно.
- **hierarchical: cutout** — каждый регион в одном пути, без перекрытий;
  **mosaic** — общие рёбра смежных регионов фиттятся один раз (швов нет;
  V2-подход, реализуем и на V1-данных: рёбра трассируются с ключами, смежные
  пути собирают общие кривые).
- **centerline-режим** — порог → Zhang–Suen → скелетный граф (узлы/концы) →
  цепочки → RDP → Schneider → SVG со stroke; толщина штриха — из distance
  transform (auto) или фиксированная. Для отсканированного лайнарта это
  единственный осмысленный вывод (outline склеивает параллельные штрихи в блобы).
- **Вход «маски вместо RGBA»** — фасад принимает либо растр (кластеризация сама),
  либо готовые слои-маски с цветом. Ключ к сценарию A: дизер-документ уже
  квантован — маски по цветам палитры идут в трассировку напрямую.
- **Пресеты** — встроенные (default/photo/poster/bw/pixel/lineart) +
  пользовательские в IndexedDB.

## 5. Гибридные сценарии (фаза 2, дизайн)

**A. Дизеринг → вектор.** Импорт с дизерингом даёт палитровый растр; его
трассировка «в лоб» порождает тысячи спекл-кластеров. Правильный путь: маски по
цветам палитры → трассировка мимо кластеризации; границы регионов — сеточно
привязанные RLE-прямоугольники/контуры (пиксель-перфект, крошечный SVG);
опционально сам дизер-паттерн кодируется `<pattern>`-заливкой (регионы остаются
векторами, текстура — тайл), что сжимает файл на порядки. Хуки уже заложены:
вход-маски, defs в compose.

**B. Лайнарт + дизер-текстуры.** Отсканированный лайнарт → centerline (штрихи —
stroke-пути); текстуры из пиксельного режима → дизеринг → маски → трассировка
(или `<pattern>`); оба результата собираются в один SVG: векторные штрихи поверх
паттерн-заливок. Пайплайны обоих режимов публикуют промежуточные стадии, поэтому
сборка — задача уровня фичи, не движка.

## 6. Решения по реализации

- Движок: чистый TS в `src/engine/trace/` (стадии — публичные функции, ≤400
  строк/файл), воркер — в фиче. Никакого Rust/wasm в рантайме.
- Эталон в тестах: `@visioncortex/vtracer@1.0.0-alpha.4` (Node-сборка, vitest),
  структурное сравнение (слои/цвета/пути ±допуски) в дефолтном V1-подобном
  режиме; собственные снапшоты — регресс-щит.
- Состояние: слайсы глобального стора (`vector`, `vector-presets`), автосейв
  работы + пресеты в IndexedDB (DB_VERSION 6).
- UI: переключатель «Пиксели | Вектор» в топ-баре; воркспейс центр-превью +
  правая колонка параметров; мобильный вариант — drawer.

## 7. Статус реализации (2026-09-27)

Реализовано и проверено (все гейты зелёные, UI проверен в браузере):

- Движок `engine/trace/`: `params` (V1-параметры + holes + centerline + пресеты),
  `quantize` (NN-chain агломерация с размерно-взвешенной дистанцией слияния —
  это даёт vtracer-поведение «мелкое сливается в крупное, градиент
  схлопывается»), `binary-layer` (спекл-фильтр + обход границ с turning
  policy, дыры по знаку площади), `simplify` (normalize + замкнутый
  RDP-стабильный к стартовой вершине), `fit-curves` (Schneider FitCurves),
  `compose` (углы/soft-якоря/сплайны, SVG-врайтер с defs-хуком), `mosaic`
  (общие рёбра смежных регионов фиттятся один раз), `centerline` (Zhang–Suen +
  2×2-прореживание до 1px, chamfer-дистанции для ширины штриха, цепочки скелета;
  короткие мосты между узлами сохраняются — кольцо не рвётся), фасад `trace`
  (вход: растр или готовые маски слоёв — хук сценария A).
- Паритет: `parity.test.ts` против wasm-оракула на трёх фикстурах
  (диск/полосы/градиент) + снапшот детерминизма.
- Состояние/хранилище: `vector.slice`, `vector-presets.slice`, `storage/vector-job`
  (автосейв источника+параметров+результата), `storage/vector-presets`,
  DB_VERSION 6; восстановление работы после перезагрузки проверено в браузере.
- Воркер: `features/vectorizer/trace.worker.ts` (трассировка вне главного
  потока, transferable-буферы, отмена устаревших прогонов по id).
- UI: ModeSwitch в топ-баре (+строка в мобильном more-меню), workspace
  (превью с зумом/панорамой/fit + ResizeObserver, сравнение
  оригинал/результат, шахматка), панель параметров с секциями и
  пресетами, импорт drag-drop/paste/клик (маршрутизация по режиму),
  экспорт SVG + копирование, i18n en/ru.
- Мост сценария A: кнопка «Векторизовать» в экспорт-поповере — рендерит холст и
  передаёт в вектор-режим (`use-vectorize-bridge`); тест входа-масок
  (`traces dithered-palette masks directly`) доказывает трассировку дизера мимо
  кластеризации.

Намеренные упрощения фазы 1 (см. §4–5): centerline-штрихи всегда чёрные;
mosaic при замкнутых общих контурах разбивает их по x-экстремумам; экспорт
дизера как `<pattern>`-заливок и редактор путей — фаза 2 (хуки заложены).
