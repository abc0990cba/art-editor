# 0008 — Landing as a hand-rolled static MPA page, editor SPA at `/editor`

Date: 2026-10-01 · Change: `openspec/changes/add-landing-seo/`

## Context

The site was a single-HTML-entry SPA: `index.html` rendered nothing without JavaScript, carried
no description/OG/canonical/favicon links, and there were no robots.txt or sitemap. Search
engines and link previews had nothing to index. `add-project-home` had explicitly deferred
SEO/SSR as a non-goal; that deferral was reversed.

## Decision

The public surface becomes a **multi-page Vite build** with hand-written static HTML:

- `/` (Russian) and `/en/` (English) are complete static landing pages — no framework, no
  React, no client rendering. Crawlers and link previews get final markup.
- The editor app moves to a second entry, `editor/index.html`, served under `/editor` (a real
  directory index, so the main entry needs no hosting rewrite); the TanStack
  Router gains `basepath: '/editor'`. Relative routes (`/`, `/p/$projectId`) and their semantics
  are unchanged; deep links become `/editor`, `/editor/p/$projectId`; the bench harness lives at
  `/editor/?bench=1`.
- Landing copy lives in the two HTML files, **not** in the app i18n dictionaries — crawlers must
  see final text without executing JavaScript. The ru/en duplication is deliberate and
  page-symmetric; `npm run seo:check` verifies structural parity.
- Artwork is **generated by the engine**: `npm run art:generate` renders demo documents through
  `buildSvg` (the same serializer as the editor's SVG export) into committed
  `public/art/*.svg`, and composes `public/og-source.svg` / `public/icon-source.svg`; the PNGs
  (`og.png`, `apple-touch-icon.png`) are one-off headless-Chrome rasterizations of those
  sources, committed. No image library is added.
- Crawler files: `robots.txt` allows all and references `sitemap.xml`, which lists exactly the
  landing pages. `editor/index.html` is `noindex`. There is **no global SPA fallback** — unknown paths
  keep returning real 404s.
- Hosting rewrites (`/editor` and `/editor/*` → `/editor/index.html`) ship as `public/_redirects`
  (Netlify, Cloudflare Pages) and `vercel.json` (Vercel); dev and preview get the same mapping
  from a small Vite middleware in `vite.config.ts`.

## Alternatives considered

- **An SSG layer (Vike / vite-react-ssg) or Astro** — rejected for now: the landing is two
  static pages with no dynamic content; a framework adds a dependency, a render layer and a
  learning curve to produce what is ultimately static HTML. The exit path stays open: nothing
  here depends on hand-rolled HTML specifically.
- **Embedding the landing in the app's `index.html`** (Excalidraw-style, app stays at `/`) —
  rejected: the visible home would remain the app's projects screen, part of the landing would
  be replaced on mount, and `/` would serve two different "products" to crawlers and users.
- **A React landing route prerendered into `index.html`** — rejected: landing copy would exist
  both as static HTML and in the i18n dictionaries with a sync risk, and the app bundle would
  load before the landing could hydrate.

## Consequences

- Canonical/OG/sitemap URLs use the reserved placeholder origin `https://ditherlab.example`
  until a real domain exists; `seo:check` warns while it is in place. Replacement touches
  `index.html`, `en/index.html`, `public/robots.txt`, `public/sitemap.xml`.
- Landing styling is plain CSS over the app's design tokens (`landing/landing.css` imports
  `src/index.css` wholesale — tokens and all seven `data-theme` blocks come along; no color
  value is duplicated). The page follows the stored app theme via an inline pre-paint bootstrap
  that mirrors `state/ui.slice.ts`.
- `landing/` and `scripts/` sit outside `src/`: tsconfig, oxfmt/oxlint targets and knip entries
  were extended; dependency-cruiser still cruises `src` only.
- Keeping the Vite dev/preview middleware in sync with the hosting rewrite files is a
  maintenance coupling; all three ship in this repo.
