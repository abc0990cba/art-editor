# Рендер-ядро Дизерлаб: масштабирование до 4096×4096+

**Решения по умолчанию**: цель 4096² (архитектура масштабируется до 8192²); WebGPU — ускоритель поверх Canvas 2D-фолбэка; Rust/WASM — отдельной фазой; суб-детализация ограничена произведением `размер × sub`; **обратная совместимость старых сохранений не хранится** (приложение одной из первых версий — формат меняется без миграции).

## 1. Диагноз текущего ядра

Реальный лимит — **`MAX_SIZE = 512`** (`src/engine/doc.ts:306`), «500» — только в комментариях. Узкие места, все — на главном потоке (ни одного Worker/OffscreenCanvas/WebGPU/WASM в репо):

- **Данные**: плотные `Uint16Array cells` + `Uint32Array cellObj`, иммутабельно-клонирующая семантика — каждый коммит штриха делает `.slice()` всего буфера (`paint.slice.ts:67,157`, `floodfill.ts:60`, `selection.slice.ts:204`). При 4096²: **96 МБ аллокаций на один штрих**.
- **Геометрия**: `buildGeometry` (`geometry.ts:699`) — полный скан буфера + **SVG path-строка на каждую закрашенную ячейку** (`shapeGeometry:110–196`), затем `Path2D` из мегабайт `d`-строк (`png.ts:11–29`). Пересобирается на **каждый коммит, зум, пан, resize** (`canvas-stage:455`, арт-битмап `canvas-stage:1822–1849`). Метаболлы — поле `Float32Array` + marching squares; outline — отдельное поле **на каждый цвет** (`outline.ts:37–43`).
- **Undo**: zundo хранит целый Doc на шаг, floor 8 шагов игнорирует бюджет (`store.effects.ts:17–24`) → до ~768 МБ истории при 4096².
- **Persistence**: autosave = `JSON.stringify(serialize(doc))` в **localStorage** каждые 800 мс (`store.effects.ts:96–108`) — квота ~5 МБ падает молча; thumbnail = полный `buildGeometry` на каждый save; `listProjects` грузит все документы целиком.
- **React**: `setHover` создаёт новый объект на каждый pointermove → полный ре-рендер 2439-строчного компонента; `bumpStaging` ре-рендерит его же на каждый кадр штриха; коммит → ре-рендер всего shell (`app.component.tsx:218`), SettingsPanel, LayersPanel.
- **Алгоритмика**: `blobCells` O(size⁴), radial fill сканирует всю сетку, flood fill выделяет маску всего холста на каждый seed, node-графы считаются **дважды** без мемоизации (composite + sceneGeometry), нет интерполяции между pointer events.
- Уже есть и хорошее (сохраняем): инкрементальный `stagingPreview`, кэш `Path2D` по строке, reuse scratch-буферов, rAF-коалесинг, разреженная сериализация scene-дерева.

## 2. Целевая архитектура

### 2.1 Данные — тайловая модель (главный рычаг)
Новый `src/engine/tiles.ts`: холст = сетка тайлов **128×128 ячеек** буфера. `Tile { cells: Uint16Array, cellObj: Uint32Array|null, version, inkCount }`; пустые тайлы не существуют. `Doc` получает `tiles: Map<number, Tile>` + `version`; плотные `cells/cellObj` — **ленивая проекция** на переходный период, горячие пути переводятся на тайловый доступ.
- Коммит штриха пишет только dirty-тайлы (типично 1–10 тайлов ≈ 0,1–1 МБ вместо 96 МБ).
- Композит сцены (`scene.ts buildComposite`) → **инкрементальная запечка** по dirty-тайлам (bbox + symmetry orbit изменённого объекта).
- **Undo-патчи вместо снапшотов**: шаг = `{tileKeys, before[], after[]}`; память ∝ чернилам. Бюджет истории 256 МБ с реальным enforcement.
- Селект-клик, `fillSelection`, `attributeFill` — по ink-индексу, без полных сканов.

### 2.2 Рендер Canvas 2D — тайловый растровый кэш (работает везде)
- Растровый кэш: `OffscreenCanvas`/`ImageBitmap` на `(tileId, zoomBucket, styleVersion, paletteVersion)`; кадр = `drawImage` видимых тайлов.
- **Зум/пан без пересборки**: пан — translate; зум — мгновенный blit предыдущего bucket, затем прогрессивная дорисовка видимых тайлов в бюджете ≤4 мс/кадр (от центра вьюпорта). Zoom-bucket — квант ~1.5×.
- Геометрия строится **по тайлам** → строковые фрагменты и `Path2D` кэшируются per-tile, ревалидация по `version`.
- **RLE-прямоугольники** для square/pixel-стилей: слияние соседних ячеек одного цвета в прогоны → в 10–100× меньше path-фрагментов.
- Сетка: LOD + viewport culling; оверлей: ants — bbox-only + пауза вне вьюпорта; hover — только при смене ячейки и не во время штриха.

### 2.3 Web Workers
- **Compute pool** (2–4 воркера): тайловая геометрия, flood fill, node eval, image-ops, сериализация, PNG-экспорт (OffscreenCanvas в воркере), миниатюры. Транспорт: transferable dirty-тайлы; `SharedArrayBuffer` + Atomics — zero-copy режим при COOP/COEP (фича-детект, один интерфейс).
- **Render worker (поздняя ступень)**: `transferControlToOffscreen`, главный поток шлёт только команды.
- Node eval: мемоизация `(hash(graph)+hash(inputInk)) → Map` — убивает двойное вычисление.

### 2.4 WebGPU tier (ускоритель, Canvas 2D — фолбэк)
`src/features/canvas/gpu/` за контрактом `Renderer`: инстанс на закрашенную ячейку (x, y, значение, стиль-флаги), палитра-текстура, SDF rounded/chamfer в фрагментном шейдере → 1–2 draw call'а на холст; зум/пан — смена uniform. Шахматка/сетка — шейдерные проходы; метаболлы — поле в compute (контуры пока CPU по тайлам). Асинхронная инициализация, `device.lost` → откат на 2D-путь. Скриншот-pariti-тесты двух путей.

### 2.5 WASM/Rust ядро (после профилирования M2/M3)
Крейт `ditherlab-core` (wasm-pack → `src/engine/wasm/pkg`), JS-фолбэки сверяются property-тестами: flood fill (scanline), поле метаболлов + marching squares (SIMD), image-ops, RLE-геометрия, бинарная сериализация. Vite: `vite-plugin-wasm` + top-level-await; `arch:check` — engine может импортировать engine-wasm.

### 2.6 Persistence — без обратной совместимости
- **Формат v4 — единственный**: заголовок + RLE-упакованные тайлы; scene-дерево — как сейчас (sparse). **Загрузчик v3 и легаси flat-режим удаляются** (`project.ts` deserialize, `layers: null`-ветки, пресет/import-клампы упрощаются); старые автосейвы/проекты в IndexedDB не мигрируют — принимается их утрата (ранняя версия приложения).
- Autosave → **IndexedDB** (store `autosave`), debounce 2–5 с + сохранение на `visibilitychange`; localStorage — только настройки UI.
- `listProjects` → метаданные+thumbnail отдельным индексом, документ лениво; проверка «чистой загрузки» — по version/хешу, без двойного stringify.

### 2.7 React-горячие пути
- Разбить `canvas-stage` (2439) на `base-renderer` / `overlay-renderer` / `input-controller` / `view-controller` (+`gpu/`).
- **Штрих без ре-рендеров**: staging → прямой вызов отрисовки (без `bumpStaging`); React — только на commit. Hover — ref + rAF, `setHover` только при смене ячейки.
- Коммит: узкие селекторы вместо `s.doc` в shell/SettingsPanel/LayersPanel; `hasContent` → счётчик `inkCount`; мемоизация пресет-матчинга.

## 3. Фазы

- **M0 Baseline + лог производительности (первым шагом)**:
  - `npm run bench` (vitest bench, node) — детерминированные сценарии движка: `buildGeometry` 512²/2048²/4096² при 5/15/30% ink, кадр `stagingPreview`, `syncDoc`/composite, flood fill, symmetry stamp, serialize/deserialize, resize. Фиксация: прогрев, N итераций, median/p95.
  - Браузерный bench-режим (`/index.html?bench=1`, dev-only страница): реальные кадры — полный redraw, зум/пан (ms/кадр), e2e штрих (pointerdown→rAF→commit), ants fps; экспорт JSON-отчёта.
  - **Артефакт `bench/PERFLOG.md` + `bench/results/baseline-<дата>.json`**: окружение (машина, ОС, браузер/node, версия приложения), точные команды воспроизведения, таблица baseline-метрик. **Обязательный ритуал каждой фазы: замер до → изменение → замер после → строка в логе**: | дата | фаза | метрика | до | после | Δ% | что изменило (ссылка на PR/файлы) |. Итоговые % считаются от baseline M0.
- **M1 Ядро данных**: тайлы + инкрементальная запечка + патч-undo + `inkCount`; `MAX_SIZE=4096` (единая константа, `project-dialog` перестаёт хардкодить 512), лимит `size×sub ≤ 16.7M`; удаление v3/flat-легаси. Гейт: все тесты зелёные, история ≤ 256 МБ при 4K², запись в PERFLOG.
- **M2 Рендер v2 (Canvas 2D)**: тайловый растровый кэш, прогрессивный зум/пан, RLE-прямоугольники, grid LOD, ants/hover-фиксы, разделение canvas-stage, штрих без ре-рендеров. Гейт: зум/пан 4K² < 8 мс/кадр, коммит < 16 мс, 500² без регрессий, запись в PERFLOG.
- **M3 Воркеры + persistence**: compute pool, autosave → IDB v4, ленивый каталог. Гейт: главный поток свободен ≥90% времени штриха, load 4K² < 1 с, запись в PERFLOG.
- **M4 Алгоритмика**: кэш tip-масок, bbox-скоупинг radial fill/flood, однопроходный outline (лейблы вместо поля на цвет), мемо node eval, Bresenham-интерполяция между pointer events, индекс triangle `cellAt`. Каждый пункт — с замером в PERFLOG.
- **M5 WebGPU**: инстансный пиксельный рендер + шейдерные сетка/шахматка/SDF, фолбэк и авто-детект. Гейт: зум/пан 4K² = 60 fps, visual parity с 2D, запись в PERFLOG.
- **M6 WASM/Rust**: перенос подтверждённых профилировщиком ядер, SIMD, бинарная сериализация в воркере. Запись в PERFLOG (JS vs WASM).
- **M7 Харденинг**: стресс-тесты 2K²/4K², синхронизация лимитов UI, дизайн-ревью HUD, обновление AGENTS.md; опционально CI-задача с рэтчетом бюджетов `perf-stress`.

## 4. Бюджеты (приёмочные, 4096², 10% ink)
Штрих pointermove→растр p95 < 8 мс; коммит < 16 мс; зум/пан < 8 мс/кадр (GPU: 60 fps); load < 1 с; save < 300 мс; resident-память < 600 МБ; история ≤ 256 МБ; 512² — без регрессий. Каждая фаза отчитывается Δ% от baseline M0.

## 5. Риски
- **Старые сохранения будут утеряны** при переходе на v4 — осознанно принято (первая версия приложения).
- **SAB** требует COOP/COEP — режим опционален, transferable — по умолчанию.
- **WebGPU** есть не везде — 2D-путь остаётся полноценным, не деградацией.
- **Двойной рендерер** — общий контракт `Renderer` + скриншот-pariti тесты.
- **Замеры шумят** — фиксированные сценарии/итерации, median/p95, окружение фиксируется в логе; бюджеты в тестах с запасом.
- Каждая фаза самодостаточна и отгружаема; M5/M6 переносятся без ущерба — M1–M4 уже дают ~40–80× на критических путях.
