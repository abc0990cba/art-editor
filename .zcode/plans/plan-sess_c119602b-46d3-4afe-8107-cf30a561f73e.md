# Technical Documentation System for Ditherlab (English, OpenSpec-compatible, full sweep)

## Goal

Complement OpenSpec (business/behavior contracts in `openspec/`) with a durable **technical** documentation layer in `docs/`: architecture, decision records (ADRs) explaining *why* each technology choice was made, and per-module/per-feature technical docs with diagrams. Everything in English. Existing docs brought up to date with the current code and translated. New docs are added via one reusable template scenario.

**Boundary rule** (documented in `docs/README.md`, AGENTS.md, and `openspec/config.yaml`): OpenSpec = behavior contracts (SHALL/scenarios, what the product does). `docs/` = durable technical truth (how it works, why it was built this way). A change's `design.md` stays change-scoped; at archive time its durable decisions are promoted into `docs/decisions/` ADRs and the affected `docs/modules/` pages are updated.

## Key research findings (ground truth for the docs)

- **Rust is NOT in the production app.** The vtracer Rust tool was ported to pure TS (`src/engine/trace/`, parity-tested against the official vtracer WASM build used as a dev-only test oracle in `trace/parity.test.ts`). A bench-only Rust flood-fill spike (`bench/wasm-flood/`) showed tuned TS (3.1 ms) matches the Rust core (≈3.2 ms) — the TS loss was algorithmic, not language speed. Decision on record (PERFLOG M6 + `docs/perf-research.md` §8): **stay TS**; WASM cores gated on "≥2× faster AND ≥20% end-to-end share"; the crate is kept for future cores (metaball field, trace). This story becomes ADR-0003/0004.
- Render pipeline: store dispatch → `buildGeometry(doc)` → `StyledPath[]` (RLE fast path for plain pixels) → `drawGeometry` Canvas2D (`Path2D` cache). No WebGL/WebGPU (deferred, M5). Stroke staging uses an imperative rAF loop; `stagingPreview` returns null for outline/metaball/texture/non-square grids → the "stroke-fallback cliff".
- Layers: `engine` (pure TS, no React) ← `storage` (IndexedDB v7) ← `state` (zustand, 16 slices + zundo) ← `features`/`app`, enforced by dependency-cruiser. Two production Web Workers (trace, gradient) with request-id + transferable-ArrayBuffer protocol.
- Existing docs gaps: no architecture doc, no ADRs, stale README architecture tree, duplicated run commands in README, 12/13 OpenSpec spec Purposes are TBD placeholders, no English versions of RU docs.

## Content specification

**Templates.** `module-tech-doc.template.md`: Purpose & scope / Responsibilities / Module map (file table) / How it works (Mermaid where it earns one) / Data structures / Algorithms & complexity / Invariants & constraints / Performance characteristics (link benches + PERFLOG rows) / Testing / Related decisions (ADR links) / OpenSpec capabilities covered / Known limitations. `adr.template.md`: Numbered title / Status (accepted | superseded by NNNN) / Date / Context / Decision / Alternatives considered / Consequences / Evidence (bench files, PERFLOG rows, OpenSpec changes).

**Architecture docs** — Mermaid diagrams (flowchart for layers matching `.dependency-cruiser.cjs`, sequence for dispatch→draw, ER-style for doc/scene/IDB). Sourced from code + `docs/perf-research.md` + PERFLOG.

**ADRs** — each cites real evidence: 0002 cites PERFLOG M5; 0003 cites `flood-wasm.bench.ts` numbers, `bench/wasm-flood/src/lib.rs`, the gate criteria and future-core list; 0004 cites `src/engine/trace/` + `trace/parity.test.ts` oracle; 0005 cites the slice composition in `editor.store.ts`; 0006 cites `storage/db.ts` v7 + autosave; 0007 defines the promotion flow step-by-step.

**Module docs** — every doc lists real file paths and line-anchored facts from the code (e.g. fallback matrix `geometry.ts:186–198`, `GraphNode.pos` in `nodes/types.ts:137`, worker protocol in `trace.worker.ts`). Target 80–250 lines each; a Mermaid diagram only where it clarifies (~10–12 total). Performance sections cite existing bench numbers, never invent new ones.
