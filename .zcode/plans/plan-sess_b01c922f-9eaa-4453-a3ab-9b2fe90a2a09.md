# План: производительность сетки + переработка цветов + выделение

Проект: glyph-editor (React 19 + Canvas 2D + Zustand). Диагностика подтверждена: при 500×500 на **каждый кадр штриха** полностью пересканируется буфер (до 2,36 млн ячеек), заново строятся path-строки всех ячеек, копируется весь буфер, заново парсятся Path2D и перерисовываются все линии сетки — на больших сетках это лаги.

## 1. Производительность отрисовки (главное)

**Инкрементальный рендер во время штриха** (ядро фикса):
- Закоммиченный рисунок кэшируется в offscreen-канвас, перерисовывается только при смене doc/view (не на каждый кадр штриха).
- Во время штриха видимый канвас компонуется из дельты: blit арт-слоя → выбить стёртые staged-ячейки (`destination-out`) → фон через `destination-over` (кэшированный паттерн) → нарисовать геометрию **только staged-ячеек** (O(штрих) вместо O(буфер)). Скругления (radius, per-corner, cornerStyle, sizeX/sizeY) учитываются — staged-геометрия строится теми же билдерами с тем же стилем.
- Fallback на полный rebuild: staged-ячейки элементов с renderMode `metaball`/`outline` (их контур глобальный); квадратный pixels-режим — инкрементальный.

**Дополнительные оптимизации:**
- Кэш Path2D по строке пути (Map с лимитом) вместо WeakMap по identity (`png.ts`) — убирает re-parse при commit/панорамировании.
- Линии сетки — кэшированный Path2D по (gridType, bw, bh, sub) вместо тысяч moveTo/lineTo за кадр.
- `mergedCells`: переиспользуемый scratch-буфер вместо `slice()` на каждый кадр.
- `elementGeometry`: Map по element id + хэш стиля вместо `groups.find(sameElementStyle)` (глубокое сравнение на каждую ячейку).
- Кэш контуров выделения/ховера в select-режиме (сейчас marching squares с аллокацией Float32Array на 2,36 млн на каждое движение мыши).
- Метаболы при активном штрихе на больших сетках — предпросмотр с пониженным качеством поля, полная пересборка на commit.
- **Проверка**: bench-скрипт (buildGeometry/staging-кадр при 500×500, разные радиусы) + ручная проверка в браузере на 500×500 и 512×512×sub3.

## 2. Инструмент цветов

- Блок палитры — **на самый верх правой колонки, закреплён (sticky)**, не скроллится, открыт по умолчанию.
- **Двойной свотч как в Photoshop**: передний = текущий цвет кисти (клик — ColorPicker, рядом hex); задний со смещением = ластик, отрисованный классической «шахматкой» прозрачности с красной диагональю. Клик по свотчу ластика активирует инструмент «ластик». Активный инструмент подсвечивает свой свотч кольцом.
- Подсветка активного свотча во всех сетках (recent/quick/палитра): акцентное кольцо со смещением + внутренняя обводка с автоконтрастом (белая на тёмных, чёрная на светлых) вместо смены цвета рамки.

## 3. Выделение (лучшие практики PS/Illustrator)

- **Внешняя обводка**: контур рисуется в scratch-канвас, внутренняя половина штриха выбивается `destination-out` → обводка **никогда не перекрывает** пиксели/край фигуры; толщина ~2px в экранных пикселях + внешняя тёмная гало-подложка для контраста на любом фоне.
- **Marching ants**: анимированный пунктир (rAF только пока есть выделение; статика при `prefers-reduced-motion`).
- Заливка-тинт снижена 0.14 → 0.08 — перекраска под выделением остаётся видимой.
- При перетаскивании выделения муравьи **следуют за призраком** (контур из doc+staging), а не остаются на старом месте.
- Доп. фича: бейдж размера выделения W×H (в ячейках) у рамки на overlay.
