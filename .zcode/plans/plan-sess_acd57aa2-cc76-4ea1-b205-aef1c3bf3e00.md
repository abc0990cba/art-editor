# Градиентная векторизация растра: исследование и план внедрения

## 1. Ответ на главный вопрос

Да, это реализуемо целиком в браузере на нативном SVG — от простых градиентов до сложных многослойных переходов. Ниша практически пуста: Vectorizer.ai (сильнейший конкурент) поддерживает «full 32-bit color», но его заливки палитровые — градиентные заливки он не заявляет; Image Trace в Illustrator — только плоские цвета. Ключевое открытие исследования: **Illustrator при импорте SVG теряет `mix-blend-mode` (multiply/screen) и `plus-lighter`** — а именно на них строятся уровни 2–4 в плане другого LLM. Поэтому целевой профиль — **AI-safe SVG**: только то, что AI импортирует надёжно (`linearGradient`/`radialGradient` + `gradientTransform`, `stop-opacity`, `clipPath`, обычный z-order). Сложность выражается числом слоёв и стопов, а не blend-режимами.

## 2. Итоги исследования

**Алгоритмы (по уровням):**
- **Уровень 1 — параметрическая подгонка на регион** (базовый, проверенный путь): аффинная регрессия цвета → SVD/собственный вектор 2×2 → направление линейного градиента; центр радиального из систем нормалей градиента изображения; профиль «t → медианный цвет» → стопы через RDP-упрощение по ΔE → точные цвета стопов прогонкой Томаса. Так работал ArDeco (Lécot & Lévy, 2006) — регионы с линейными/квадратичными заливками.
- **Уровень 2 — слои по остатку**: база + жадное добавление цветовых пятен туда, где ошибка максимальна (в AI-safe — с normal-смешением и стопами прозрачности; multiply/screen — опциональный «богатый» профиль для веба).
- **Уровень 3 — гауссовы сплаты**: подход подтверждён — [GaussianImage (ECCV 2024)](https://github.com/Xinjie-Q/GaussianImage) представляет картинку суммой 2D-гауссианов (8 параметров, Adam-фиттинг). SVG-маппинг (эллипс + одноцветный `radialGradient` с прозрачностью) в библиотеке отсутствует — делаем сами.
- **Уровень 4 — mesh / diffusion curves**: автогенерация градиентного меша — Sun et al., SIGGRAPH 2007; diffusion curves — Orzan et al. 2008, [PVG 2020](https://cg.cs.tsinghua.edu.cn/papers/TVCG-2020-PVG.pdf); обзор — [Gradient Art (Inria)](https://inria.hal.science/hal-00760068/PDF/GradientArt.pdf). В браузере считаются WebGL, для SVG экспортируются тесселяцией; meshgradient браузеры не рисуют (выброшен из SVG 2), AI его из SVG не получит.
- **Дифференцируемая доводка**: [DiffVG (2020)](https://people.csail.mit.edu/tzumao/diffvg/diffvg.pdf) доказывает класс; в браузере — свой рендерер на TF.js/WebGL (только полировка после аналитической подгонки).

**Совместимость с Illustrator** (определяет архитектуру): надёжно — градиенты с `gradientUnits="userSpaceOnUse"`, `gradientTransform`, `stop-opacity`, `clipPath`; теряется — `mix-blend-mode` (подтверждено сообществом, молча пропадает), `plus-lighter` (CSS-свойство, AI не знает), conic (в SVG нет). Прямая запись `.ai` не планируется: AI открывает SVG нативно; stretch — PDF (axial/radial shadings; mesh-shadings типа 6/7 — рискованно, нужен спайк).

**Библиотеки**: готовых JS-библиотек фиттинга градиентов нет (potrace/imagetracerjs/vtracer — плоские заливки). Математика небольшая и рукописная — это соответствует конвенциям репо (`fit-curves.ts` уже содержит МНК + Newton–Raphson). Зависимости (ml-matrix, culori, delaunator, tfjs) не добавляем на этапе 1; вернёмся к вопросу на уровнях 3–4.

## 3. Архитектура пайплайна (общая)

Импорт → предобработка (даунскейл до 256–512 по длинной стороне, блюр σ≈0.7–1.5 против бандинга/дизеринга/JPEG) → сегментация на гладкие регионы + контуры (переиспользуем существующую трассировку) → per-region подгонка solid→linear→radial→elliptic с выбором простейшей модели, укладывающейся в допуск ΔE → слоистое уточнение по остатку → модель документа `{shape, paint, opacity, clip}` → два рендерера (SVG-строка и математический — обязаны совпадать, sRGB, source-over) → **оракул качества**: сериализованный SVG рисуется браузером в canvas, сравнивается с оригиналом (mean/p95 ΔE2000 + тепловая карта). Ошибка меряется по настоящему рендеру, а не по внутренней модели.

## 4. Точки встраивания (установлены разведкой кода)

- **Движок**: новый `src/engine/gradient/` — чистые функции, ≤400 строк/файл (ratchet). Из `engine/trace/` переиспользуются `traceMask`/`simplifyLoop`/`fitChain`/`mosaicPaths` (контуры-клипы); вход `TraceInput {kind:'layers'}` уже позволяет подавать регионы-маски; `composeSvg(width, height, paths, defs?)` (compose.ts:140) имеет хук `<defs>` — `SvgPath.fill` примет `url(#id)`.
- **Важно**: `quantize.ts` (`mergeDistance`) намеренно схлопывает градиенты в плоские слои — градиентной сегментации нужен свой проход, `quantize` не расширяем.
- **Воркер**: по образцу `trace.worker.ts` + `use-vector-trace.hook.ts` (протокол `{id, params, rgba} → {svg, stats}`, сброс устаревших по id); добавить progress-сообщения — итеративный фиттинг дольше трассировки.
- **Третий воркспейс (будущие этапы)**: `kind:'gradient'` в union `projects.ts:4` + фабрика + ветка в `normalizeProject`; ветка в `project-route.component.tsx:88`; свой zustand-слайс по образцу `vector.slice.ts` (`loadXxxEntry`/`saveCurrent` с гардом по kind); `KindOption` в `new-project-dialog`; карточка, top-bar, i18n (сначала en, затем ru — иначе tsc упадёт); IDB-миграция не нужна (`params: unknown` + normalize-паттерн обратно совместим); delta-спека `project-library` в openspec. Arch-правила: engine чистый, фича не импортирует фичу.

## 5. Первый исполняемый шаг — прототип движка (этап 1)

Scope: уровень 1 без UI. Всё в `src/engine/gradient/`, node-тесты на синтетике.

Файлы (чистые функции, каждый ≤400 строк):
1. `types.ts` — `RegionPixels`, `GradFit` (kind: solid|linear|radial, геометрия, стопы), `FitOptions {dEдопуск, maxStops}`
2. `color.ts` — sRGB↔Lab, ΔE76/ΔE2000 (рукописно, ~60 строк)
3. `linalg.ts` — solve3x3, собственные 2×2 симметричной, прогонка Томаса, квадратичная регрессия (гейт «регион гладкий»)
4. `fit-linear.ts` — аффинная подгонка C≈C0+J·p → JᵀJ → главный собственный вектор (направление), t-проекции, x1/y1/x2/y2; критерий линейности λ2/λ1
5. `profile.ts` — бины по t с медианами → RDP-упрощение с ΔE-метрикой → позиции стопов
6. `stop-colors.ts` — точные цвета стопов при фиксированных позициях (Томас) + координатный спуск позиций ±δ
7. `fit-radial.ts` — Собель по размытому изображению, центр из 2×2 IRLS (веса |g|), t=|p−c|/r → переиспользует profile+stop-colors
8. `model-select.ts` — solid→linear→radial, простейшая модель с mean ΔE ≤ допуск (+ штраф за параметры, BIC)
9. `render.ts` — математический рендер фита в Float32-буфер (метрики + тесты)
10. `compose.ts` — маленькая сериализация defs+fill в AI-safe SVG (для будущей интеграции и тестов структуры)

Тесты (синтетика, эталон известен точно):
- кусочно-линейный градиент 2–6 стопов, углы 0/30/90°, с бандингом 8-бит, шумом, дизерингом: mean ΔE2000 ≤ 2, ошибка направления < 1°, число стопов ±1
- радиальный: ошибка центра < 1.5 px
- сплошной регион → выбран solid; «радуга» (нелинейный) → модель корректно отвергнута (гейт для уровня 2)
- юнит-тесты: RDP-стопы, Томас vs прямое решение, sRGB↔Lab round-trip

Гейт приёмки: `npm run format:check && npm run lint && npm run arch:check && npm run knip && npx tsc --noEmit && npm test` — всё зелёное + пороги синтетики выше. Реальные картинки пойдут на этапе 2, когда появится воркер и превью. Коммитит человек; предложу текст (`feat(engine): gradient region fitting — linear/radial fits, ΔE stop simplification`).

## 6. Дорожная карта после прототипа

- **Этап 0 (ручной спайк, 1 файл)**: таблица AI-импорта — тестовый SVG (градиент+transform, stop-opacity, clipPath, multiply-слой, plus-lighter-группа) открывается в вашем Illustrator; фиксируем, что выживает.
- **Этап 2**: сегментация гладких регионов (трассировка границ существующим пайплайном + классификация гладкости квадратичной регрессией) + градиентный воркспейс (kind gradient): превью, ΔE-карта, пресеты по паттерну `TRACE_PRESETS`.
- **Этап 3**: AI-safe слои — жадный фиттинг по остатку (пятно максимальной ошибки → новая полупрозрачная заливка), список слоёв, хэндлы градиента на канве, «перефитить с зафиксированными».
- **Этап 4**: дифференцируемая доводка (свой WebGL/TF.js-рендерер: внешний LM-цикл по геометрии, внутренние линейные стопы), затем сплаты (схема GaussianImage → эллипсы+radialGradient с clipPath), затем mesh/diffusion curves в WebGL с тесселяцией для экспорта.

## 7. Риски

- AI-импорт blend-режимов — снимается AI-safe-профилем; спайк этапа 0 закрывает неопределённость фактами.
- Производительность фиттинга на 2048² — подгоняем на даунскейле 256–512, координаты масштабируем обратно.
- Бандинг/дизеринг/JPEG — предблюр, медианы в бинах, робастные веса (Huber).
- В воркере нет progress/cancel — расширение протокола на этапе 2.
- SVG на сотни сплатов тормозит рендер — лимит элементов в UI.
