# Pixel-style expansion — 4-phase roadmap

Goal: make per-pixel drawing radically more diverse. Four systems, each shipped green before the next. Order: **B (inlays) → A (fields) → C (glyph/emoji inlays) → D (variety pack)**, since the user's headline ask is the inner-figure system.

Research base: existing engine has 28 cell shapes (registry-driven), texture/halftone decorations, noise jitter (the only per-cell size field today), presets, node graph. Gaps vs similar tools (halftone generators, mosaic dispersal, Truchet tilings, Aseprite FX): no per-cell inner content, no grid-wide size/rotation/offset field, no per-cell shape variation, no hollow-cell style. Verified integration points: per-cell loop `shapeGeometry`/`pushCell` (src/engine/geometry/shape.ts:287, jitter consumed at :302), non-square twin `grids/geometry.ts:77`, color groups `Map<value, frags>` (shape.ts:272,358), stroke support already renders in canvas (output/png.ts:40) and SVG (output/svg.ts:31), RLE gates `runMerge`/`plainSquare`/`textured` (shape.ts:247-285).

## Phase B — Inlays: "figure inside every pixel"

New `InlaySettings` block on `PixelStyle` (flows into ElementStyle freeze + PresetConfig automatically):
`{ shape: CellShapeId | 'none', scale 0.1..0.9, offsetX/offsetY −0.5..0.5, rotation, thickness, points, colorMode: 'slot'|'darken'|'lighten'|'toneDark'|'toneLight', slot, depth }` — shape reuses the existing 28-shape registry.

Implementation:
1. `engine/core/doc.ts` — type + `defaultDoc()` defaults. `engine/core/project-json.ts`/`project-parse.ts` — serialize/parse+clamp. Extend `samePixelStyle` (doc-style.ts) so style equality sees the block.
2. New `engine/color/shade.ts` — mix-hex-toward-black/white helper (hsv utils exist in color.ts).
3. Rendering in `shapeGeometry`: after the main figure fragment, emit the inlay fragment into a **second group map** keyed by derived color id; groups emit after base paths → paint on top. Inlay forces the per-cell loop (extend `runMerge` gate: inlay==='none'). Update `stagedCellPath` (live stroke preview) and `gridPixels` (non-square grids). Pixels mode only in v1; texture holes stay on the base figure (no interaction).
4. UI: "Inner figure" group in `style-section.component.tsx` (pixels block, near ShapePicker): none+shape grid (reuse `ShapeTileGrid`), scale/offset/depth sliders, color-mode chips, palette slot picker. Wire via `useStyleTarget().applyStyle` like existing knobs.
5. i18n `style.inlay.*` in en+ru messages; presets: normalize in `presets/index.ts` + built-in seeds; node `style.pixel` gains inlay params (optional, cheap).
6. Tests: geometry snapshot for an inlay doc (base + inlay groups, ordering), parse/normalize round-trip, `samePixelStyle` cases.

## Phase A — Cell fields: "funnel and friends"

Grid-wide per-cell modulators. New pure module `engine/effects/fields.ts` (deterministic, like `effects/jitter.ts`):
- **Size field**: `funnel` (radial falloff), `fountain` (inverse), `rampX/rampY/rampDiag`, `waveX/waveY`, `rings` (radial waves), `spiral`, `checker`, `pyramid`, `edges`, `dome`. Params: `fieldAmount`, `fieldMin` (min scale), `fieldAngle`, `fieldPeriod`, `fieldPhase`, invert.
- **Align field (rotation)**: `center` (face center), `outward`, `swirl` (tangent), `truchet` (seeded 90° steps → emergent quarter-circle patterns with any shape), `wave`.
- **Offset field**: `vortex`, `magnet`, `drift` (sine), `scatter` (seeded).

New `PixelStyle.field: { size, align, offset, amount, min, angle, period, phase, seed, invert }`.
Implementation: consumed in `pushCell` right where `jitterAt` is consumed (shape.ts:302) + `grids/geometry.ts:100`; extend `runMerge`/`plainSquare` gates; deterministic per cell → dirty-tile cache keeps working (jitter precedent). UI: "Field" chip group + sliders in StyleSection. Presets: normalize + one-click built-in seeds: Funnel, Vortex, Fountain, Ripple, Sunburst, Truchet Weave (thumbnails auto via `presetPreviewDataURL`). Tests: field evaluator units (symmetry/determinism), funnel geometry snapshot, perf-stress row + PERFLOG entry.

## Phase C — Glyph & emoji inlays (dot-matrix)

`inlay.source: 'shape'|'glyph'`, `glyph: string` (any char/emoji), `resolution 4..16`, `dotShape: CellShapeId`, `dotScale`. Engine samples the char: offscreen canvas `fillText` → `getImageData` → threshold → n×n bitmap (canvas-in-engine precedent: output/png.ts), LRU-cached per char+font+size, in a new small module (e.g. `engine/glyph/emoji-sample.ts`). Each cell draws mini-dots for on-bits — pure vector, identical in canvas/PNG/SVG. Perf: res² fragments per inked cell — cap resolution, add perf ratchet, PERFLOG row. UI: char TextField + resolution slider + dot-shape grid inside the inlay group.

## Phase D — Variety pack

- **Shape ramp**: `shapeRamp: CellShapeId[]` + `shapeRampBy: 'tone'|'field'|'x'|'y'|'radial'|'random'` — per-cell shape pick (dark cells circle → light cells star, or seeded confetti). Fragments concat per color group already, so only gates change.
- **Hollow cells**: `stroke: { width 0.02..0.3, colorMode, fillVisible }` — emits stroke paths; canvas+SVG support already verified (connectors use it).
- **~10 new shapes** via the standard registration (union + registry row + HIT_OF + FRAG_OF + 2 i18n keys each): quadrant arc (the Truchet tile), bowtie, hourglass, parallelogram, keyhole, eye, clover, burst, wave-strip, half-ring.
- **Preset batch 2**: Confetti, Emoji Mosaic, Blueprint (hollow), Shape Parade (ramp) + field/inlay combos.

## Execution protocol (every phase)

1. OpenSpec change proposal first (repo workflow: specs + design + tasks), then implement.
2. Layer order within a phase: engine → serialization/presets → store wiring → UI → i18n (en+ru) → tests.
3. Mandatory green chain after every change: `npm run format:check` → `lint` → `arch:check` → `knip` → `tsc --noEmit` → `test`. Perf-relevant phases add a PERFLOG row. UI phases run the design-review skill before handoff.
4. Respect file-size caps (400/150) — fields, shade, and emoji-sampling live in new small modules; `cell-shapes/*` and `geometry/shape.ts` are near caps — new per-cell logic goes into the new modules, not into shape.ts.
5. After each phase: propose the ready Conventional Commit message (human commits).

Risks: `samePixelStyle`/`elementStyleKey` must compare new style blocks (else element-scope restyle dedupes wrongly); texture stays plain-square-only (unchanged); RLE fast path must stay intact when all new features are 'none' (gate checks are the only hot-path cost).
