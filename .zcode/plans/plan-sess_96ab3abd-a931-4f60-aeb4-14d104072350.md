## Goal

Make cell figures a first-class, engine-wide artistic system: **8 new cell forms** (organic: crescent moon, teardrop, flower, semicircle; graphic: gear, asterisk, lightning, chevron) and **close the integration gaps** so shapes + tone-driven sizing (AM halftone) work on every grid type and in the node graph.

Baseline fact: the per-cell shape engine already exists on master (`engine/cell-shapes.ts`, `PixelStyle.shape/shapeParams/toneSize/toneSizeMin`, ShapePicker UI, forms presets/ramps). This round extends it; nothing is rewritten.

## Part 1 — Eight new cell forms

**1a. Split `cell-shapes.ts` (will exceed the 400-line lint cap).** Keep the public API stable (15 import sites stay untouched):
- `engine/cell-shape-defs.ts` — `CellShapeId` (+8 ids), `CELL_SHAPE_IDS`, `ShapeParams`/`ShapeParamKey`, `DEFAULT_SHAPE_PARAMS`, `CELL_SHAPES` registry entries, `normalizeShapeParams`, `sameShapeParams`, `paramsOf`, `isCurvedShape`, `isCellShapeId`.
- `engine/cell-shapes-geom.ts` — unit polygons, hit tests, `cellShapeFragment`, `CellShapePlacement`, `shapePreviewPath`.
- `engine/cell-shapes.ts` — facade re-exporting both. If geom still exceeds limits, split polygon-family builders into `cell-shape-poly.ts`.

**1b. Geometry per form** (each: registry entry with param list + `curved` flag, unit silhouette for `cellShapeHit`, fragment branch in `cellShapeFragment`; all get rotation free via existing probe-rotation/poly placement):
- `moon` — crescent: outer circle r=0.5 minus offset inner circle; params `thickness` (crescent fatness), `rotation`; hit = two-circle test; fragment = two arc subpaths (explicit tip-to-tip arcs).
- `teardrop` — apex + round belly, like heart: cubic fragment + flattened polygon hit; params `rotation`.
- `flower` — `points` = petal count (3..12), `thickness` = petal slimness, `rotation`; hit via polar rose formula; fragment via cubics per petal (fragment length comparable to heart — no 90-point polygons, per-cell path strings must stay compact).
- `semicircle` — dome (flat side down): arc + close; hit = half-disc; params `rotation`.
- `gear` — `points` = tooth count (3..12), `thickness` = tooth depth, `rotation`; polygon like `starPoly` but flat-topped teeth.
- `asterisk` — `points` = arm count, `thickness` = arm width; exact union silhouette of n crossed bars (tip corners at r=0.5, valleys at w/sin(π/n)).
- `lightning` — fixed bolt polygon; params `rotation` (+`thickness` width squeeze).
- `chevron` — ^ bar arrow; `thickness` = bar width, `rotation`.

Design constraint for all: form center (0.5, 0.5) must be inside the silhouette so `glyphSetForm`/`glyphSetFormDuo`/`glyphSetFormMorph` ramps work without special cases (they scale probes about center; ring is the only special case today).

**1c. Wiring that is automatic** (no code, must not regress): ShapeTileGrid/ShapePicker tiles, brush tips (`brush.shape`), fab-panel, element style grouping (`elementStyleKey`, `samePixelStyle` — already include shape fields), serialization (`normalizeStyle`, `normalizePresetConfig` via `isCellShapeId`), SVG/PNG export, `PixelStylePreview`.

**1d. i18n** — `cellform.moon/teardrop/flower/semicircle/gear/asterisk/lightning/chevron` in both `en.messages.ts` and `ru.messages.ts`.

**1e. AM presets** — extend `engine/preset-lists-forms.ts` with one preset per new form (Crescents, Teardrops, Blooms, Half-Moons, Gears, Asterisks, Bolts, Chevrons). Add a small `formPreset()` factory first so the file stays under the 400-line cap (~33 → ~12 lines per preset).

**1f. Forms glyph ramps** — 8 entries in `BUILT_IN_GLYPH_SETS` (`glyph-form-moon12`…, family `forms`, `form: '<id>'`) via `glyphSetForm`; picking one in the glyph editor auto-sets the cell form (existing `applyGlyphSet` behavior).

## Part 2 — Shapes + toneSize on hex/triangle/radial grids

- `engine/grid-geometry.ts` pixels branch: when `style.shape !== 'square'`, draw each cell via `cellShapeFragment` on the cell polygon's bbox (with `sizeX/sizeY` and tone scaling about bbox center); `square` keeps today's native-polygon path (hex cell stays hexagon — documented in the module comment).
- Extract the tone-scale formula (currently inlined in `geometry-shape.ts:100-109` and duplicated in `geometry.ts` staging) into one helper next to `hexLuminance` in `engine/color.ts`; use it in all three places. No behavior change.
- `features/settings-panel/style-section.component.tsx`: show the Shape group (ShapePicker + toneSize) for pixels mode on **any** grid type (currently gated `doc.gridType === 'square'`); RoundingControls logic stays (`!curved`), `isSquareGrid` prop unchanged.
- Check `stagingPreview` gating in `geometry.ts`: if it lacks a gridType guard, non-square strokes must fall back to full `buildGeometry` (prevents square-cell flash before rebuild); square-grid path keeps the shape branch it already has.

## Part 3 — Node graph knobs

`engine/nodes/styles.node.ts` `style.pixel` node gains: `shape` (`select`, options `CELL_SHAPE_IDS`), `thickness`/`points`/`rotation` numbers, `toneSize` bool; `evaluate` writes them into the element style (same pattern as `style.render`'s select cast). Procedural per-object forms become possible in the scene graph.

## Tests

- `cell-shapes.test.ts`: per new form — fragment starts with `M` and is non-empty; hit(0.5,0.5)=true, corner expectation per shape; hit count invariant under rotation 90/180/270; `paramsOf` matches registry; param clamps.
- `geometry.test.ts` / `geometry-tone.test.ts`: flower-or-gear doc with `toneSize` — `stagingPreview` parity with `buildGeometry`; serialize round-trip.
- Grid tests: hex grid + `circle` → arc-bearing fragments; `toneSize` changes fragment size; hex + `square` → native polygon unchanged (regression).
- `presets.test.ts` / `projects.test.ts`: new shape id round-trips through normalization.
- Glyph ramp test: each new form's ramp starts empty and ends solid (existing pattern in `glyph-generators-art.test.ts`).
