# Dither Effects Library — full implementation in one session

Same catalog and architecture as before; the change: **all phases are implemented in this session, back-to-back**, with the app kept green and fully regression-tested at every phase boundary. Every feature lands wired into its UI surface (import dialog, fills, textures, node graph), not engine-only.

## Execution order (each phase ends with the full regression gate)

**Gate after every phase:** `npm run format:check` → `npm run lint` → `npm run arch:check` → `npm run knip` → `npx tsc --noEmit` → `npm test` (full suite) — all green before the next phase starts. Final gate additionally runs `npm run build`.

- **Phase 0 — Dither registry (engine refactor).** New `src/engine/dither-registry/` (split per family to respect the 400-line ratchet): every effect as data `{id, group, kind, paramsSchema, impl}`; dispatch, `ORDERED_DITHERS`, `DITHER_GROUPS`, galleries and presets validation derive from it. No behavior change; existing 24 dithers keep pixel-identical output (pinned by existing tests).

- **Phase 1 — Algorithm completion (~32 ids).** Ordered: bayer32, rosette-45°, elliptical-dot, Euclidean, line screens h/v/diag, IGN (port), blue-noise-16, spiral, concentric-rings, sunburst, phyllotaxis, zigzag, weave, twill, houndstooth, fractal-noise, Yliluoma-1/2 (palette-aware), custom matrix (user GlyphTileSet via `glyphSetToField`). Diffusion: Sierra-2, 1D-horizontal, anisotropic x/y, scan-path variants (Hilbert = true Riemersma, spiral, diagonal, column, seeded-random), noise-modulated threshold, edge-aware adaptive strength. Conformance tests per family: determinism, strength-0 ≡ nearest, palette bounds, tone monotonicity. i18n en+ru for every id; galleries auto-derive.

- **Phase 2 — Vector halftone screen engine (flagship).** `src/engine/screen-engine.ts`: unified MarkShape registry (28 cell shapes + line/ellipse), tone mapping (size / density / shape-morph / twist-angle), lattices (square, rotated, hex, diamond, radial rings, sunburst, spiral, phyllotaxis), line systems (straight, wavy, cross-hatch, engraving flow lines), stippling (weighted Lloyd/Voronoi + Poisson-disk), multi-ink screens (duotone/tritone/**CMYK rosette** 15/75/0/45°). Dual output: evenodd vector path fragments (ADR-0002-safe) + boolean cell masks. Wired into: import dialog (screen dither family + params), fill `screen` upgrade, texture panel (non-dot halftone marks — closes the documented "dots only" gap), `mod.halftone` node.

- **Phase 3 — Text / glyph / ASCII dithering.** `src/engine/text-raster.ts` (+ADR): font rasterizer → boolean tiles → GlyphTileSet / vector fragments; classic ASCII ramps (5–70 levels), custom user ramp strings, letter-density ramps, braille 2×4 cells, word-as-mark fills, char→GlyphTileSet generator family, `source.text` node, **ASCII text export mode**. Import glyph modes extended.

- **Phase 4 — Hybrid specials & custom content.** Per-tone-band hybrid dithering (different algorithm per shadow/mid/highlight band), posterize+jitter, gradient-map duotones, edge-outline + halftone-fill combos, bloom-before-dither tuning; custom matrix/kernel/ramp editors surfaced from the glyph editor.

- **Phase 5 — Node presets, galleries, docs.** ~10 new node preset recipes, gallery/UX polish, i18n sweep, `docs/modules/dither-and-patterns.md` + related module docs updated, bench entries + `bench/PERFLOG.md` rows for heavy algorithms (stippling, Yliluoma, Hilbert), final full regression + build.

## Process guarantees

- Engine stays pure (no React), allocation-free hot paths (follow `import-diffusion.ts`); heavy algorithms get bench coverage + regression ratchets in `perf-stress.test.ts` style.
- OpenSpec change folders written per phase before its implementation (`add-dither-registry`, `expand-dither-algorithms`, `add-halftone-screen-engine`, `add-text-dithering`, `add-hybrid-dither-effects`), following the `expand-dither-toolkit` template; docs promoted at the end.
- New UI follows design conventions; design review after UI-touching phases.
- Ready commit messages proposed at each phase boundary (per AGENTS.md the human runs `git commit`).
- Non-goals unchanged: no video/animation/temporal effects, no batch processing.

Phase 0: write the `add-dither-registry` OpenSpec proposal, implement the registry refactor, run the full gate, then continue straight into Phase 1 without stopping.
