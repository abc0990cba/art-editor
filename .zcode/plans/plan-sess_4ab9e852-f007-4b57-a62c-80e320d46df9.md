# VTracer web-app parity + six site sample presets in the vectorizer

## What research established

Your app already contains a full TypeScript port of vtracer V1 (`src/engine/trace/`, verified against the official wasm oracle in `parity.test.ts`) and the vectorizer panel (`src/features/vectorizer/vector-params-panel.component.tsx`) already exposes every site control with matching **defaults** (speckle 4, color precision 6, gradient step 16, corner 60, segment 4, splice 45, precision 8; Color + Stacked + Spline on load). The 6 site samples exist on the deployed site (`visioncortex.org/vtracer/assets/samples/…`) with exact pre-selected settings I extracted from the site's `index.js`.

## Parity gaps to fix (controls that don't yet behave like the site)

1. **Slider ranges**: site uses speckle **1–16** (app 0–128), gradient step **0–255** (app 0–128), segment length **3.5–10** (app 0–10). Corner/splice/precision already match.
2. **Segment length visibility**: on the site, corner + segment length + splice appear **only in Spline mode**; the app always shows segment length → move it into the spline-only group (engine still applies it to polygon simplification, same as the site).
3. **Mode chip naming**: site calls the third path mode "Pixel" (exact cluster boundary); the app labels it "Edges" → rename to "Pixel"/«Пиксель» and order chips Pixel | Polygon | Spline like the site.
4. Engine clamp for `layerDifference` widens 0–128 → 0–255 in `normalizeTraceParams` (site range); app-only extras (centerline tracer, threshold/invert, mosaic, holes, iterations, visible path precision) stay — they're additions beyond the site, not deviations.
