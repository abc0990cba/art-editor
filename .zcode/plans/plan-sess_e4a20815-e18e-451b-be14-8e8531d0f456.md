## Root cause

The grid is **Rhombille** ("Ромбиллы" — every hexagon split into three lozenges). It indexes cells `0 … 3·cols·rows`, but three committed code paths still assume the square buffer `cols·sub × rows·sub`, so every index ≥ `cols·rows` is silently dropped:

1. **`buildComposite`** — `src/engine/core/scene.ts:258` allocates `doc.cells` with `cols·sub·rows·sub`; the guards at `scene.ts:311/318` drop everything past it. Rhombille index = `(row·cols+col)·3+face`, so survivors need `row < rows/3` — **exactly the top third of the canvas**. Ink below is erased at commit.
2. **`mod.offset` graph node** — `src/engine/nodes/transforms.node.ts:39-44` decodes `x = i % bw, y = floor(i/bw)` with square dims and drops `y ≥ bh`. Every drawn stroke auto-attaches this node with `dx=0, dy=0` (`src/state/store-internals.util.ts:18-20, 75`), so it re-truncates even if the composite were fixed. A numeric check confirms it keeps 256/768 cells = the top third.
3. The live preview inherits it: `sceneGeometry` sizes its per-layer scratch from `doc.cells.length` (`src/engine/geometry/index.ts:54`).

The same ceiling also breaks **octasquare** (count ≈ 2·cols·rows — unpaintable gap cells). The codebase already knows the right formula: `src/engine/core/project-parse.ts:322-327` allocates `Math.max(square, grid.count)` with a comment saying exactly that — `buildComposite` just never got the same treatment. The uncommitted `add-cell-inlays` diffs are purely additive rendering plumbing and are **not** the cause (verified; all 226 grid/geometry tests pass).

## Changes

1. **`src/engine/core/scene.ts`** — `buildComposite`: allocate `Math.max(cols·sub·rows·sub, makeGrid(...).count)` (mirror project-parse, incl. `radialEven` and `gridRotation`); pass the (cached, identity-stable) `grid` into the `evalGraphMemo` EvalInput.
2. **`src/engine/nodes/types.ts` + `eval.ts`** — add optional `grid?: Grid` to `EvalContext`/`EvalInput` (type-only import; flows to nodes via `withNodeRng`'s spread).
3. **`src/engine/nodes/eval-memo.ts`** — memo compares `grid` by identity (stable: `makeGrid` caches per type/cols/rows/even/rot).
4. **`src/engine/nodes/transforms.node.ts`**:
   - `mod.offset`: `dx===0 && dy===0` → passthrough (the every-stroke case — the actual bug); square-buffer grids (`count === bw·bh`, incl. hex/triangle/brick/rotated square) keep the existing exact index math; compound lattices (rhombille, octasquare) translate in point space: `cellAt(center(i) + (dx·w/cols, dy·h/rows))`, dropping off-grid results.
   - `mod.symmetry`: compound lattices expand via the existing grid-aware `gridSymmetryOrbit` (`src/engine/effects/symmetry-grid.ts:275`) instead of the square decode.
5. **`src/engine/geometry/index.ts`** — pass `grid` in the two EvalInput sites (`sceneGeometry` ~:88, `metaballOverlayContours` ~:208) so per-layer previews benefit too.
6. **`src/features/nodes-editor/node-editor-canvas.component.tsx`** (~:196) — pass `grid` in the preview EvalInput so editing dx/dy in the node editor previews correctly on rhombille.

Out of scope, verified non-issues: the in-progress inlay work (untouched); procedural source nodes / parametric shape graphs remain square-buffer-based (pre-existing, separate concern); flat legacy docs already keep count-sized buffers from `convertGridDoc`.
