# Fix the Vercel `/editor/` 404 (trailing-slash rewrite gap)

**Root cause (verified on the live deployment):** the file is deployed — `/editor/index.html` returns the app shell — and the rewrites for `/editor` and `/editor/:path*` work. But Vercel's routing, once `vercel.json` defines rewrites, no longer resolves directory indexes implicitly, and no rewrite source matches `/editor/` (the `:path*` needs at least one segment). The CTAs, the manifest `start_url` and the bench URL all use `/editor/` → 404.

## Changes

1. **`vercel.json`** — add the missing explicit rewrite (before the `:path*` rule):
   `{ "source": "/editor/", "destination": "/editor/index.html" }`
2. **`public/_redirects`** — add the same explicit `/editor/` line for Netlify/CF Pages (defensive; their static layer usually serves directory indexes first, but be explicit and symmetric).
3. **Docs** — one-line amendment in `docs/decisions/0008-landing-static-mpa.md` (hosting rewrites bullet: Vercel bypasses directory-index resolution once rewrites are defined, hence the explicit trailing-slash rule) and a follow-up checkbox in `openspec/changes/add-landing-seo/tasks.md`.

No source, build or landing changes — the deployed `dist` is already correct.
