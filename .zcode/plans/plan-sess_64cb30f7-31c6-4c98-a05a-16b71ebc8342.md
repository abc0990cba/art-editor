# Engine restructure + complete documentation index

## Goal

1. Replace the flat `src/engine/` root (~200 files) with ~16 domain folders, so navigation is by meaning, not by filename prefixes.
2. Split the two remaining engine monoliths (`doc.ts` 460 lines, `fillpatterns.ts` 452 — both on AGENTS.md's pending list).
3. Produce a structured, detailed documentation system: a new engine index page plus deepened per-domain module docs with clickable links to source files.
4. Keep every gate green after every stage (`format:check`, `lint`, `arch:check`, `knip`, `tsc`, `test`); no behavior changes, no perf work.

Decisions taken (defaults, since unanswered): **engine-only scope** (state/storage/features already foldered/sliced), **strip family prefixes** inside folders (`texture/hatch.ts`, not `texture/texture-hatch.ts`), **keep relative imports** (repo convention: 259 relative engine imports vs 11 alias uses in vendored shadcn only).

## Verified constraints (from exploration)

- `.dependency-cruiser.cjs` matches `^src/engine` as a prefix — subfolders are safe; no rule changes required.
- `.oxlintrc.jsonc` `overrides` pins ~50 exact paths → every moved pinned file must be re-pointed; one dead pin exists (`src/features/projects/projects-dialog.component.tsx`); several pins are stale-loose (geometry 829 vs actual 369, scene 804 vs 385, symmetry 621 vs 358, grids 551 vs 265, palettes 457 vs 15, project 487 vs 9, doc-style 444 vs 113, app.component 352 vs 16).
- Hardcoded engine paths: `scripts/generate-landing-art.ts` imports `demo-project.ts`, `doc.ts`, `project.ts`, `svg.ts` (update during their moves). `editor/index.html` → `main.tsx` (untouched).
- All imports are explicit-relative; `tsc --noEmit` catches every missed rewrite. Tests/benches are glob-discovered (portable). `bench/results/engine-bench.json` embeds old paths → regenerate baseline at the end.
- Precedent for the target style already exists: `nodes/`, `gradient/`, `trace/` folders and the `nodes/index.ts` barrel (knip-clean).
- Known pre-existing quirk to preserve, not fix: `texture-field ⇄ texture-hatch` value cycle stays intra-folder.

## Migration stages

Each stage: `git mv` (history preserved) → rewrite imports repo-wide until `tsc` is clean → re-point `.oxlintrc.jsonc` overrides → run the full gate chain → propose the Conventional Commit message (you commit; I never run `git commit`).

2. **`cell-shapes/` + `grids/`**
3. **`shapes/` + `paint/`**
4. **`effects/`**
5. **`texture/`** (without fillpatterns yet)
6. **`geometry/`**
7. **`import/`**
8. **`presets/` + `demos/`** (+ `scripts/generate-landing-art.ts` import fix)
9. **`core/`** (doc/scene/project — the hub, highest import churn; remaining script fixes)
10. **Split `core/doc.ts`** → model/constants stay in `doc.ts`; `doc-resize.ts` (`resizeDoc/changeSub/fitSub`), color resolution per cohesion; re-export from `doc.ts` so external imports stay stable. Remove its ratchet pin.
11. **Split `texture/fill.ts`** → pattern/gradient coordinate math vs `applyFillStyle`/selection fill vs data (already separate). Remove its pin.
12. **Ratchet hygiene**: re-point every moved pin; right-size stale-loose caps to actual+2 or delete pins now under global caps; delete the dead `projects-dialog` pin.
13. **Docs overhaul** (below) — after paths settle so all links are final.
14. **Bench**: `npm run bench` to regenerate `bench/results/engine-bench.json`; add an English PERFLOG row (structural reorg, no perf delta expected, baseline regenerated).

## Documentation deliverable (stage 13)

Follows ADR-0007 (docs own technique, `docs/modules/` is the mandated location, English, code-anchored claims):

- **New `docs/architecture/engine-map.md`** — the engine index: annotated folder tree (folder → one-line responsibility → key entry points), one mermaid cluster-dependency diagram, table domain → module doc page → public API entry. Rows added to `docs/README.md` Architecture table.
- **Deepen the ~16 engine-related pages in `docs/modules/`** (doc-and-scene, geometry, grids, shapes, texture, dither-and-patterns, glyphs, image-import, paint-tools, palettes-and-presets, symmetry, effects, render-outputs, node-graph, gradient-workspace, vectorizer). Each gains: an annotated folder map, a step-by-step data-flow walkthrough of its pipeline (e.g. how a texture is drawn: `TextureSettings` → region scan → flecks/halftone/hatch → SVG fragments → `StyledPath` → Canvas2D; how rendering works: store commit → `buildGeometry` → layers → paint), and a per-file table of key exports.
- **Clickable source links**: convert backtick path references to relative markdown links (`[texture/region.ts](../../../src/engine/texture/region.ts)`); symbols stay as backtick names; no `#L` line anchors (they drift — current convention kept). Same treatment in the architecture trio where engine paths appear.
- **`docs/architecture/overview.md`** engine module map updated to the new tree; **`docs/README.md`** fixes: add missing ADR-0009 row, index the stray `docs/roadmap-vector-effects.md`, consciously amend the "~10 Mermaid diagrams total" budget to allow 1–2 diagrams per engine deep-dive page; template note in `docs/templates/module-tech-doc.template.md` preferring markdown file links.
- Final link-integrity check: script-verify every source link in touched docs resolves to an existing file.
