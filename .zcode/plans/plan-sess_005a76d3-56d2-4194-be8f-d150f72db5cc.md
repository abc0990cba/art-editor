# Большое расширение сеток пиксельного воркспейса

**Цель:** радикально разнообразить сетки — новые решётки (ромб 45°, изометрия, кирпич, усечённый квадрат «срезанные углы»), свободный поворот всей сетки, 8 новых форм ячеек, больше ручного контроля (заливка строк/столбцов, саб-детализация, жирные линии сетки), генератор сеток в нод-графе, демо и пресеты. Всё с проверками после каждой фазы.

**Почему это дёшево расширяется:** движок уже универсален — `Grid` (center/polygon/cellAt/edgeNeighbors), `attachEdgeMap` (соседи по рёбрам полигонов), `traceSilhouette`, `gridMetaball`, `convertGridDoc` работают с любой решёткой; формы ячеек — реестр `CELL_SHAPES`. Новая решётка = билдер + `GridType` + whitelist парсера + i18n; новая форма = запись реестра + силуэт + фрагмент + 2 ключа i18n.

---

## Фаза 1 — Решётки diamond, iso, brick (новый файл `src/engine/grids-lattices.ts`)

- **diamond** — та же квадратная сетка, повёрнутая на 45° (прямая просьба). Точный O(1) `cellAt` через сдвиговое преобразование: u = x+y, v = x−y — ромб становится квадратом в (u,v); col = floor(x+y), row = floor(x−y).
- **iso** — классические изометрические ромбы 2:1 (пиксель-арт тайлы). Тот же трюк: u = x/2+y, v = x/2−y.
- **brick** — кирпичная кладка: прямоугольники 1×0.5, нечётные ряды сдвинуты на 0.5. 6 соседей по рёбрам — посчитает `attachEdgeMap`.
- Интеграция: `GridType` + `GRID_TYPES` (grids.ts), dispatch в `buildGrid` → новый файл (старый grids-builders.ts 374 строк, не раздуваем), `cellCoordLabel` (col/row), whitelist в `project-parse.ts:274`, i18n `grid.<id>` + `.desc` en/ru. В диалоге проекта (Select по `GRID_TYPES`) появятся сами.
- Тесты: round-trip `cellAt(center(i))` для всех ячеек, степени соседей (diamond 4, iso 4, brick 6), BFS-связность, полигон в границах канваса, рендер forms/outline/metaball на новой решётке, round-trip проекта.

## Фаза 2 — Решётка octasquare (усечённый квадрат: октагоны + квадраты)

- Точное замощение 4.8.8: октагон с центрами с шагом 2, малые квадраты в углах между ними. `polygon(i)` возвращает октагон или квадрат по чётности (полигон per-cell — составные замощения поддерживаются).
- O(1) `cellAt`: ближайший октагон-центр, зона угла (|dx|>rin && |dy|>rin) → квадрат-гэп, иначе октагон-тест max(|dx|,|dy|)≤R и |dx|+|dy|≤cut.
- Соседи: октагон 8, квадрат 4 — `attachEdgeMap` посчитает сам. Тесты: round-trip, степени, связность, hit-пробы в угловых зонах, рендер.

## Фаза 3 — Поворот сетки: параметр `gridRotation` (0..360°)

- `Doc.gridRotation?: number` (default 0) + сериализация в `ProjectJSON`/parse (число, clamp, invalid → 0).
- Обёртка в новом файле `src/engine/grid-rotate.ts`: `rotatedGrid(base, deg)` — вращает center/polygon вокруг центра канваса, `cellAt` через обратный поворот, `angleOf/cellByAngle` со сдвигом угла; радиусы не меняются. Мемо-ключ `makeGrid` расширяется rotation (все ~8 call-sites makeGrid получают параметр: grids.ts docSize/gridConvertMap, floodfill, scene-resize, staging hook, canvas-stage).
- Диспетч рендера: хелпер `isLatticeDoc(doc)` = `gridType !== 'square' || rotation !== 0` в `geometry.ts` (оба места) — повёрнутый квадрат идёт через `gridBuildGeometry` (нативный полигон уже повёрнут), `stagingPreview` возвращает null (обновить perf-stress контракт), оверлей сетки — через polygon-path ветку.
- Углы канваса вне ячеек остаются непрокрашиваемыми — как у radial сегодня.
- UI: в диалоге проекта слайдер 0–355° (шаг 5) + быстрые чипы 0/15/30/45/60 (виден для square/hex/triangle/diamond/iso/brick; radial — без него). Hex 30° = flat-top, square 45° = ромб — бесплатные вариации.
- Конвертация типа/размера работает в базовой (неповернутой) системе, rotation просто остаётся на doc.
- Тесты: round-trip `cellAt(center(i))` при 45°, полигоны = повернутые базовые, сдвиг `cellByAngle`, раздельный кэш, round-trip проекта с rotation, stagingPreview=null на повёрнутом квадрате.

## Фаза 4 — 8 новых форм ячеек (20 → 28)

**pentagon, octagon, capsule, trapezoid, shield, leaf, egg, arrow.**
- Все полигон-базированные: силуэт в `cell-shape-geom.ts` + HIT через `unitPolyHit` + FRAG через `roundedPolygonPath`. Файл 318 строк — новые силуэты/хиты в новом `cell-shape-ext.ts` (таблицы мержатся в HIT_OF/FRAG_OF), чтобы не пробить рэтчет 400 строк. Параметры: capsule/trapezoid/shield/arrow — `thickness`, pentagon/octagon — `rotation`, leaf/egg — `rotation`.
- Автоматически подхватятся: пикер (ShapeTileGrid), слайдеры params (paramsOf), нода style.pixel, глиф-рампы (cellShapeHit), пресеты форм, канвас/экспорт/саб-сетка.
- i18n `cellform.<id>` + `.desc` en/ru. Тесты клеточных форм — табличные по реестру, покроют сами; добавить точечные probe-тесты хитов.

## Фаза 5 — Контроль воркспейса

- **Заливка строки/столбца**: `fillScope` расширяется `'row' | 'column'` (квадратная сетка): чипы в canvas-section для square, `fillSeeds` в staging hook заполняет весь ряд/столбец (с учётом sub). Ответ на «линии или столбцы».
- **Саб-детализация 1×/2×/3×**: у `setSub` сейчас нет UI — добавляю чипы в canvas-section (square only). Головой движок уже умеет.
- **Жирные линии сетки (мажор/минор, «как миллиметровка»)**: `gridEmphasis` (0=выкл, 2..16) в ui.slice; в канвасе второй Path2D для каждой N-й линии квадратно сетки, толще/темнее. UI — слайдер рядом с «Pixel grid».
- Тесты: fillSeeds row/column, сериализация новых полей store не нужна (UI-состояние), снапшот оверлея не требуется.

## Риски и решения

- **Рэтчеты размера**: новые решётки/поворот/формы идут в новые файлы (grids-lattices, grid-rotate, cell-shape-ext, generators.node), старые не раздуваем; canvas-section/project-dialog дробим при необходимости.
- **Перф**: квадратный fast-path (RLE, runMerge, plainSquare) не трогаем — повёрнутый квадрат уводится на общий путь как hex сегодня; `cellAt` новых решёток — O(1); attachEdgeMap строится один раз в мемо-кэше makeGrid.
- **`noUncheckedIndexedAccess` выключен** — пишем в существующем стиле проекта.
