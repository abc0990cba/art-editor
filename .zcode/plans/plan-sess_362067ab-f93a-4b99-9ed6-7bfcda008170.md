## Fix: compare wipe must show the vector only on the right side

**Root cause** — `src/shared/ui/compare-split.component.tsx:42-47`: the left layer (original photo) is rendered across the whole artwork box *underneath*, and only the right layer (traced SVG) is clipped to the right of the divider. In binary (black-and-white) trace mode the SVG is a single `#000000` ink layer with a transparent background (`src/engine/trace/compose.ts:140` — no background rect; `trace.ts:93-101` — binary emits one black layer), so right of the divider the original photo shines through everywhere except the ink strokes. That is exactly the reported bug.

**Change** — one semantic fix in the shared wipe component:

1. `src/shared/ui/compare-split.component.tsx`
   - Clip the **left** layer to the left of the divider too: add `style={{ clipPath: `inset(0 ${100 - split}% 0 0)` }}` to the left wrapper (line 43); the right wrapper keeps its existing `inset(0 0 0 ${split}%)`.
   - Update the doc comment (lines 5-11): left of the divider shows only the left layer, right of it only the right layer; transparent areas of the right layer show the parent viewport's checkerboard.

**Why nothing else needs to change**
- Both `CompareSplit` consumers (vector preview `vector-preview.component.tsx:65`, gradient preview `gradient-preview.component.tsx:112`) sit inside `PanZoomPreview`, which already paints a checkerboard under the artwork as its transparency indicator (`pan-zoom-preview.component.tsx:103-112`). After the clip, the right side shows the traced vector over that checkerboard — black binary ink reads fine on it, and transparency is shown honestly.
- The gradient preview becomes strictly more correct as well (transparent result gaps show the checker instead of the photo).
- The import dialog's own `BeforeAfterPreview` already paints an opaque checker backdrop under its result canvas, so it never had this bug — untouched.
