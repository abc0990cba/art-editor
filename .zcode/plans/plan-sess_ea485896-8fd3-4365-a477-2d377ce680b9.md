# Пиксельные стили по элементам + выделение и редактирование путей

## Суть
Сейчас стиль (скругления, режим рендера «пиксели/контур/metaball», настройки metaball, текстура) — глобальные поля документа, и «штрихов» как объектов не существует (только буфер ячеек `Uint16Array` с индексом цвета). План переводит редактор на послойную модель:

1. **Каждый штрих/фигура/заливка фиксирует снимок стиля на момент рисования** («по элементам»). Изменение настроек после этого влияет только на новые штрихи.
2. **Тумблер в разделе «Стиль»: «По элементам» ↔ «Глобально»**. В глобальном режиме всё рендерится как сейчас (живая переркраска всего холста); переключение обратно в поэлементный режим не разрушает уже зафиксированные стили.
3. **Инструмент «Выделение» (V)**: клик — выбрать элемент (Shift+клик — добавить/убрать), правка его стиля и текстуры в правой панели (слайдеры показывают значения элемента и применяются к выделению живьём, undoable), Del — стереть, Ctrl+A — выбрать всё, Esc — снять. **Перетаскивание** выделенного элемента мышью переносит его ячейки вместе с цветом и стилем (v1 — только на квадратных сетках).
4. Соседние штрихи с **одинаковым** стилем рендерятся одной группой (metaball-блобы сливаются, контур без внутренних силуэтов), но выбираются по отдельности.
5. По умолчанию новые холсты — режим «по элементам»; старые проекты (JSON/автосохранение) мигрируют в глобальный режим без потерь.

Репозиторий использует OpenSpec-процесс, поэтому сначала создаются артефакты изменения, затем реализация.

## 1. OpenSpec-изменение `add-element-styles`
- `openspec/changes/add-element-styles/` по конвенции репозитория (proposal.md с Why/What Changes/Capabilities, tasks.md с чекбоксами, дельты спеков).
- Дельты: **pixel-styling** (поэлементные стили, тумблер scope, заморозка стиля штриха, группировка одинаковых стилей), **drawing-tools** (инструмент select: выбор, Shift-мультивыбор, перетаскивание, Del), **metaball-rendering** (поля metaball на группу элементов), **persistence** (схема v2 + миграция).

## 2. Движок (`src/engine/`)
- **doc.ts**: новый тип `ElementStyle = { style: PixelStyle; renderMode; connectivity; metaball; texture }` (полный снимок всех «стилевых» настроек, включая текстуру). В `Doc`: `styleScope: 'global' | 'element'`, `elements: ElementStyle[]`, `cellObj: Uint32Array | null` (параллельный буфер id элементов, ленивая аллокация; 0 = без элемента). В `Link`: `obj?: number`. Хелперы: `elementFromDoc(doc)` (снимок текущего стиля рисования), `sameElementStyle(a, b)` (deep-equal для группировки).
- **`resizeDoc`, `changeSub`, `convertGridDoc`** (grids.ts): переносят/ресемплят `cellObj` вместе с ячейками; `clear` в хранилище обнуляет.
- **geometry.ts**: в режиме «по элементам` `buildGeometry` группирует ячейки по id элемента → сливает группы с deep-equal стилями → для каждой группы строит виртуальный doc (style/renderMode/connectivity/metaball/texture из элемента) + под-буфер ячеек + под-множество линков и вызывает существующие билдеры (`shapeGeometry` / `outlineGeometry` / `metaballGeometry` / `gridBuildGeometry`). Глобальный режим — прежний код без изменений. Порядок отрисовки — по первому появлению (стабильный).
- **Staging** (geometry.ts): добавляется `objs?: Map<index, number|null>` + `pendingElement?: ElementStyle` — превью штриха в процессе рисования рендерится со своим снимком стиля.
- Экспорт SVG/PNG и превью пресетов идут через тот же `buildGeometry` — паритет «превью = экспорт» сохраняется автоматически.

## 3. Хранилище (`src/state/store.ts`)
- `setStyleScope(scope)`: undoable; при переходе в «по элементам» все уже нарисованные ячейки materialизуются в один элемент №0 со снимком текущего глобального стиля (картинка не меняется), `cellObj` аллоцируется.
- `paintCells` / `fillAt` / `addLinks`: в режиме «по элементам» штампуют id нового элемента (снимок стиля рисования; если идентичный элемент уже есть — переиспользуют его id) на все закрашенные ячейки/линки; ластик очищает id.
- Выделение — UI-состояние вне undo: `selection: number[]` (id элементов) + действия `selectElement/clearSelection/selectAll`, `restyleSelection(patch)` (применяет патч поля к каждому выделенному элементу, устаревшие элементы подчищает), `deleteSelection()`, `moveSelection(dx, dy)` (квадратные сетки: перенос ячеек+obj+линков за один undo-шаг; ушли за край — обрезаются).
- `syncHistoryLimit` учитывает +4 байта/ячейку когда `cellObj` аллоцирован.
- `applyPreset` обновляет стиль рисования (doc-поля) и добавляет `styleScope` в `PresetConfig` (normalize/matches), сам scope не переключает.

## 4. UI
- **SettingsPanel**: вверху раздела «Стиль» — переключатель «По элементам / Глобально». Когда есть выделение (и режим поэлементный), разделы **Style** и **Texture** переключаются на целевой режим: заголовок «Стиль выделения (N)», значения берутся из первого выделенного элемента, правки идут в `restyleSelection`, кнопка «Снять выделение». В глобальном режиме — как сейчас.
- **ToolRail**: инструмент «Выделение» (курсор, горячая клавиша V).
- **CanvasStage**: обработка выбора (клик/Shift/пустое место), перетаскивание с призрачным превью через Staging, подсветка выделенного в overlay-канвасе (полупрозрачная заливка + контур по marching squares маски выделения), Esc/Del/Ctrl+A, отключение brush-превью для select.
- **App.tsx**: хоткеи V / Del / Ctrl+A (Esc уже есть — расширить).
- **i18n**: все новые строки в `src/i18n/en.ts` и `ru.ts`.

## 5. Персистентность (`src/engine/project.ts`)
- Схема **v2**: `styleScope`, `elements`, `cellObj` (RLE-пары [id, длина] для компактности), линки с `obj`.
- Миграция v1→v2: `styleScope: 'global'`, `elements: []`, `cellObj: null` — старые проекты выглядят идентично.

## 6. Тесты (vitest, рядом с engine)
- Заморозка: штрих → правка стиля рисования → геометрия первого штриха не меняется, второй — с новым стилем.
- Глобальный режим: побайтовый паритет путей со старым поведением; переключение scope туда-обратно не теряет элементы.
- Слияние одинаковых стилей (metaball/outline), restyleSelection не задевает чужие штрихи, moveSelection (перенос, обрезка края, линк), resize/changeSub сохраняют obj, serialize/deserialize round-trip v2 + миграция v1.

## Не-цели (v1)

- Стиль внутри пресетов кисти, магнитное выделение/марки, трансформации (масштаб/поворот) элементов.
