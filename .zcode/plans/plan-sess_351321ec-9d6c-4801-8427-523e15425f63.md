# Pixel-mode performance: large-grid drawing & texture application

## Goal
Drawing (freehand spirals, rect/ellipse/primitives) and texture application feel instant on 1000²–4096² grids; document a measured size-capability matrix (512/1024/2048/4096²) so it's clear which sizes need caution. Decisions confirmed with user: **plain fill during drag, texture on release**; **WASM only if a post-fix bench passes the ADR-0003 gate** (≥2× vs tuned TS and ≥20% of e2e).

## Root causes (verified in code)
1. **Texture scan scales with bbox, not region**: `regionTextureFragments` (`src/engine/texture/region.ts:361-368`) iterates the lattice over the region's bounding box — O(bbox/L²); at scale 0.1 a 1000² region ≈ 5·10⁹ iterations. Sampler `regionSampler` (region.ts:170-216) does 9 `Map.get` probes per candidate (`fits`); hatch reuses it for up to 400k flag tests. **Zero caching** — every doc identity change re-emits all texture.
2. **Commit cliff**: every commit/undo does full-document `buildGeometry` + full art repaint — 11/40/120 ms at 512²/2048²/4096²; undo 38–92 ms. The repo's tile-spike bench proves dirty-tile invalidation: 4 tiles @2048² = 5.07 ms vs 113 ms whole-canvas.
3. **Stroke-fallback cliff**: textured/outline docs rebuild the whole document **per stroke frame** — grain 1.7 s/frame @2048² (`stage-paint-frame.util.ts:344` via `stagingPreview` returning null).
4. **Shape drag cost**: `stampShape` (`use-canvas-staging.hook.ts:421-767`) restamps the whole shape into `Map`/`Set` every pointer move (4M Map.set ≈ 100+ ms on a full 2048² fill); the fast pixel-bitmap preview is gated to `styleScope === 'global'` (`stage-paint-pixel.util.ts:21`) while default docs are element scope.
5. **Fill/pattern costs**: `floodRegion` allocates a full-grid mask + a fresh neighbor array per visited cell; `applyFillStyle` boxes every cell into a `Map<number,0|1>`; `screenPatternAt` computes trig per cell.

## Stages (each ends green: format → lint → arch:check → knip → tsc → test, plus bench + PERFLOG row)

### Stage 0 — Baseline & harness
- `npm run bench` (fresh baseline JSON); browser harness (`/editor/?bench=1&autorun=1`) runs at 512/1024/2048/4096² covering: pencil stroke, shape drag, shape commit, undo, fill, texture apply (grain/halftone/hatch). Record the "before" size matrix (this already answers "which sizes are slow today").

### Stage 1 — Texture engine (biggest texture win, parity-preserving)
- **1.1 Bitmap region index**: replace the `Map` spatial index in `regionSampler` with a Uint32Array grid over the bbox → `locate`/`fits` become O(1) array reads. Same iteration order ⇒ byte-identical output (validated by golden tests). Reused by hatch flag tests, halftone spray filter.
- **1.2 Early candidate rejection**: draw r1 first and apply the `keep` probability / stride before allocating `CellRand` or probing the region (per-node seeded streams make skipped nodes equivalent to rejected ones — parity holds; verified by golden tests).
- **1.3 Work cap**: halftone-style stride coarsening for scatter/grunge when lattice nodes exceed a cap (~4M) — output changes only in the regime that currently takes seconds; golden baselines regenerated; openspec delta spec documents it.
- **1.4 Fragment cache**: bounded LRU keyed by (texture settings key + region content hash) so commits, undo, zoom and unrelated edits stop re-emitting identical texture.
- **Target**: grain rebuild @2048² 1691 ms → ≤100 ms; hatch 128² 78 ms → proportionally flat at 512²; PERFLOG row.

### Stage 2 — Dirty-tile geometry + art (repo roadmap P1)
- Tile grid (~512 cells/tile), per-tile geometry cache and per-tile offscreen art canvases; commits mark dirty tiles from stroke cells; undo diffs `cells` per tile (Uint32-compare pass) to mark dirty tiles; zoom composes tile canvases; degenerates to full rebuild when >~50% tiles are dirty.
- New pure-engine modules under `src/engine/geometry/tiles/` (400-line caps respected). Gate: **commit 4096² ≤ 16 ms** with pixel-identical golden tests; undo ≤ 30 ms (patch-undo stays deferred, noted in roadmap).

### Stage 3 — Smooth in-stroke previews (roadmap P2 + shape drag)
- **3.1** Per decision: textured docs preview **plain fills during drag**; full texture on release. Kills the 1.7 s/frame cliff; update the `stagingPreview` contract matrix in `perf-stress.test.ts` + spec.
- **3.2** Extend pixel-bitmap preview to element-scope docs when the staged style is plain-square and staged palette is present (guards + golden pixel-identity tests) — the default scope gets the O(area) typed-array preview.
- **3.3** Shape-drag staging on typed arrays: per-drag Uint16Array buffer (bbox-scoped) instead of Map/Set in `stampShape`; frame reads it directly; symmetry/repeat caps unchanged.
- **3.4** Outline-mode drag previews via the same staged-plain mechanism.
- Gate: stroke frame ≤ 16 ms in all modes @2048²; full-canvas shape drag @2048² ≤ 8 ms/frame; PERFLOG row.

### Stage 4 — Fill & pattern application
- Pooled flood mask (reused Uint8Array, typed stack, no per-cell neighbor arrays); `applyFillStyle` → Uint16Array result instead of boxed Map; region-bounded `fillSelectionCells`; `screenPatternAt` trig → LUT. Gate: fill on a 1000² region ≤ 16 ms.

### Stage 5 — Interaction polish (roadmap P4)
- Hover out of the React render path (ref + imperative overlay draw); ants/idle overlay minimal redraw. Gate: no React render per cell crossing.

### Stage 6 — WASM evaluation (bench-gated, per ADR-0003)
- After Stages 1–4, bench the residual hot loops: texture lattice scan, pattern fill application, undo tile diff, metaball field, graph eval. Implement a Rust `engine-wasm` crate (wasm-pack, async init, TS fallback — pattern exists in `bench/wasm-flood/`) **only** where the gate passes; otherwise document the PERFLOG row and stay TS. Any adopted core gets an ADR + vite config updates.

### Stage 7 — Size-capability matrix & docs
- Final harness matrix per size × operation (before → after), published in `docs/research/performance.md` + PERFLOG; roadmap statuses updated; openspec change archived per checklist (ADR promotion for the texture/tile decisions).
