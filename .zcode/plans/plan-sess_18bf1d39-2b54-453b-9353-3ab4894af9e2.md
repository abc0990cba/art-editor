# Competent zoom across the app + mouse navigation

## Root cause (verified in code)

The "stuck" state comes from three combined facts:

1. **Two unequal zoom domains.** Over the canvas every wheel/pinch is hijacked for canvas zoom (`preventDefault`, no `ctrlKey` check — `canvas-stage.component.tsx:715`). The same gesture over the toolbar/panels is **browser zoom**. So you can zoom the app way in from outside the canvas, but you cannot pinch back over the canvas — and nothing in the UI mentions that `⌘0`/`⌘−` is the only way out.
2. **Browser zoom silently flips the app to the phone layout.** `lg` (1024px) is the only structural breakpoint; browser zoom shrinks the CSS viewport, so at ~125–200% on a MacBook the tool rail and right panel columns stop rendering and the canvas goes full-bleed — "only canvas on the screen".
3. **The desktop top bar overflows at 1024–1280px** (all groups `shrink-0`, no overflow handling — `app-top-bar.component.tsx:108–165`), so a small MacBook at moderate zoom gets a clipped, partly unreachable header.

## Changes

### A. Extract canvas navigation into a hook (ratchet-safe foundation)
`canvas-stage.component.tsx` is at its lint ratchet cap (1282 counted lines), so new navigation code must come with extraction — which AGENTS.md already plans for this file.
- New `src/features/canvas/use-canvas-view.hook.ts`: move the wheel-zoom effect (711–729), two-finger pinch effect (639–709) and Space/Escape key effect (731–759) out of canvas-stage, passing in the refs/callbacks they use (view/setView, drag/xform/staging refs).
- New pure `src/features/canvas/canvas-view-math.util.ts` + tests: `wheelDeltaPx` (deltaMode line/page → px), `clampedAnchorZoom` (clamp 0.5–80 + cursor anchoring), `zoomStep`.
- Lower the canvas-stage `max-lines` cap in `.oxlintrc.jsonc` to the new measured size (with the usual history comment).

### B. Mouse additions (your picks: all three)
- **Right-drag = pan**: button 2 starts a pan; `contextmenu` is suppressed over the canvas wrap (it does nothing useful there today). Joins existing middle-drag and space+drag.
- **Hand tool (H)**: new `'hand'` tool in the union (`src/state/tools.slice.ts`), icon/tooltip in `tool-icons.component.tsx`, rail entry, i18n strings. Left-drag pans; never draws. All letters are bound, so `heart` moves `h` → `Shift+H` and `h` becomes hand (Photoshop/Figma convention).
- **Shift+wheel = horizontal pan**: shift+wheel and horizontal-dominant `deltaX` (trackpad two-finger sideways) pan horizontally instead of zooming.

### C. Wheel robustness (keeping wheel = zoom)
- Normalize `deltaMode` (line-mode mice currently zoom ~7× too fast).
- Dedicated sensitivity for `ctrlKey` wheel (trackpad pinch sends small deltas and needs its own curve).

### D. Zoom keyboard shortcuts
- In the canvas key effect (same input-guard as Space): `+`/`=`/`−` zoom ×/÷1.25 around the wrap center, `0` = 100% doc scale. `F`/Fit unchanged. **⌘/Ctrl +/−/0 stay with the browser** (your choice).

### E. Browser-zoom visual hints (buttons, per your request)
- New `src/app/browser-zoom.util.ts` (+ tests): `estimateBrowserZoom()` ≈ `screen.width / innerWidth`; pure `shouldShowHint(...)`.
- New `src/app/browser-zoom-hint.component.tsx`, mounted in `project-route.component.tsx`:
  - **Situational banner** (z-20, under modals) when the effective viewport drops below the 1024px layout switch on a desktop-sized screen with zoom ≳130%: explains what happened ("browser zoom ~175% — the app switched to the compact layout; press ⌘0/Ctrl+0 to restore"), with an actionable **[Fit canvas]** button (`requestFit()`) and a dismiss remembered in localStorage.
  - **Persistent zoom chip** in the top bar whenever browser zoom ≳125% (desktop and mobile headers): shows "175%", tooltip explains ⌘0.
- Strings in `src/shared/i18n/en.messages.ts` + `ru.messages.ts`.

### F. Top bar fit in the 1024–1280 band
- `app-top-bar.component.tsx`: doc-size chip → `hidden xl:flex`, project title → `min-w-0 truncate`; if the bar still overflows at exactly 1024, theme/lang menus also hide below `xl` (Tailwind built-in `xl` only — no new custom breakpoints, per design conventions).

### G. Auto-recovery safeguard
- In the existing canvas `ResizeObserver` (canvas-stage:156–166): after a resize, if the document extent is fully outside the visible viewport (nothing but background visible), auto-`fit()` — skipped while a stroke/drag is active. Normal user zooming is never touched.
