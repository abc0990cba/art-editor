## Goal

After importing a raster image (e.g. with the `rings` dither) and applying effects, all blocks of one color must unite into **one figure** (one object per color per layer → one SVG `<path>` per color), visually identical, with fewer objects on the canvas and smaller project/SVG files. Per your choice, this ships as a **«Merge same colors» button in the layers panel** (works after import, after applying effects, and on already-broken documents).

## What exists today (verified in code)

- Import with «Объект на область» (Object per region) on creates one object per dot-region — the explosion. With it off, import already yields one object per color.
- SVG export already emits one path per color *per style group*; per-object split reappears when objects differ or «Объединять объекты» (fuseObjects) is off.
- No merge-same-color operation exists anywhere.

## Implementation

1. **OpenSpec change** `openspec/changes/merge-same-color-objects/` (proposal + spec delta + tasks), following the existing change-folder format — behavior contract for the new action.
2. **Engine (pure)** — new `src/engine/core/scene-merge.ts` (scene.ts is near its 400-line ratchet): `mergeObjsByColor(layers, scopeIds?)`:
   - Within each layer, group candidate objects by (`elementStyleKey`, single palette value). Candidates only: no `graph`, no `links`, not locked, visible, cells contain exactly one distinct value — everything else stays untouched (guarantees zero visual change).
   - Each group becomes one object placed at the bottom-most member's tree slot; cells are unioned (same value everywhere → idempotent). Never merges across layers, groups, hidden or multi-color objects.
   - Returns new layers + old→new id map (for selection), or null when nothing merged.
3. **Store** — `mergeSameColors()` in `DocSlice` (doc.slice.ts has ratchet headroom): scope = current selection when it contains objects, else the whole document; one undoable `syncDoc` step; selection remapped through the id map.
4. **UI** — icon button in the layers-panel action row (next to group/ungroup, same h-6 border-chip pattern + Tooltip). i18n keys `layers.mergeColors(.desc)` in en + ru («Объединить одинаковые цвета»). If the panel's per-function cap (272) blocks, extract the action row into a small subcomponent in the same file.
5. **Tests** — colocated vitest:
   - `scene-merge.test.ts`: merge per (layer, color); guards (graph/links/multi-value/hidden/locked/cross-layer/style mismatch); tree position; id map; no-op case.
   - Integration (scene.test.ts pattern): import a dotted two-color image with `splitConnected: true` → `mergeSameColors()` → one object per color per layer, **`doc.cells` byte-identical before/after** (visual-identity invariant), `buildSvg` emits exactly one path per color.
6. **Checks** — the mandatory loop: `format`, `lint`, `arch:check`, `knip`, `tsc --noEmit`, `npm test`; design-review skill for the panel button. Then I propose the commit message (`feat(layers): merge same-color objects into one figure per layer`) — you commit.

## Explicitly not doing

- No SVG-side path concatenation across objects: overlapping same-color subpaths under `fill-rule="evenodd"` would punch holes — a visual change you excluded.
- No automatic merge at import: the import dialog already produces one-object-per-color when «Объект на область» is off; the button covers existing and post-effect documents.

For your rings workflow the result: import → press «Merge same colors» (or import with «Объект на область» off) → one figure per color per layer, one `<path>` per color in the SVG, fewer objects, smaller files.
