# План: «Дом» + проекты двух типов + TanStack Router (модель Fresco/Figma)

## Целевая модель
Приложение открывается на **Доме** (`/`), reload возвращает **в открытый проект** (`/p/$projectId`) — адрес состояния в URL. Каждый проект имеет тип (`pixel` | `vector`), тип определяет workspace. Сохранение фоновое: autosave пишет прямо в запись проекта, кнопка Save исчезает. Глобальный переключатель «Пиксели | Вектор» убирается.

## Роутинг — TanStack Router (код-базированные роуты, без vite-плагина)
- Роуты: `/` (HomeScreen), `/p/$projectId` (редактор, workspace по типу проекта).
- Search-параметры как типизированное состояние через `validateSearch` (рукописная валидация, zod не добавляем): panelCollapsed, nodeEditor режим/сплит; запись через `replace` (не спамим историю Back).
- localStorage остаётся для префов: тема, язык, раскладка.
- SPA-fallback: dev/preview из коробки; для прод-хостинга — конфиг-строчка (отдельная заметка в tasks).
- Новая зависимость: `@tanstack/react-router`.

## Поведение при релоаде/возврате (матрица)
1. Переключение вкладок/сон — ничего не происходит (вкладка жива).
2. Выгрузка вкладки браузером — URL восстановлен → тот же проект, данные из IndexedDB.
3. Осознанный reload — **остаёмся в проекте** (Figma-конвенция); потеря ≤2 с, flush на pagehide.
4. Открытие корня приложения — **Дом** + карточка «Продолжить».
5. Краш → session restore — как (3).
6. Проект из URL удалён/не найден — мягкий fallback на Дом.
7. Состояний «работа без проекта» после миграции нет.

## Пользовательские сценарии
1. Первый запуск — Дом с пустым состоянием и «Новый проект».
2. Открытие приложения заново — Дом; «Продолжить».
3. Создание пиксельного проекта — тип «Пиксели» → имя/размер/сетка (ProjectDialog) → запись сразу в библиотеке → пиксельный workspace, URL `/p/<id>`.
4. Создание векторного проекта — тип «Вектор» → имя → векторный workspace с зоной импорта.
5. Открытие из Дома — свой workspace; векторный показывает сохранённый SVG сразу, ретрейс в фоне.
6. Выход на Дом — кнопка-домик крайняя слева (вместо папки) → `/`.
7. Сохранение — фоновое (autosave → запись, миниатюра по троттлингу и при выходе); Ctrl+S = «записать сейчас»; flush при pagehide.
8. Переименование — live-пилюля в топбаре и на карточке.
9. Дублирование/удаление — карточка в Доме, ConfirmDialog.
10. «Векторизовать» из пиксельного — новый векторный проект из PNG холста, открыть его.
11. Настройки проекта — клик по имени → ProjectDialog (edit).
12. Миграция legacy (разово) — autosave → черновик-проект; vectorJobs['current'] → векторный проект; glyph.mode удаляется.

## Изменения по слоям
- **app**: роутер (root + home + project), Search-params для view-состояния; app.component рендерит по роуту: HomeScreen | пиксельное дерево | VectorWorkspace (по kind).
- **storage**: ProjectEntry → дискриминированное объединение `kind: 'pixel' | 'vector'` (векторная запись: source-bitmap + params + svg + stats); миграция IndexedDB v6→v7 + normalize-on-read.
- **state**: ui.slice: `mode`/`glyph.mode` удаляются, view-состояние переезжает в search-параметры; project.slice привязывается к записи любого типа, пишет autosave в неё; vector.slice — рантайм-хост открытого векторного проекта.
- **features/projects**: полноценный HomeScreen — «Продолжить», сетка карточек (бейдж типа, размер, дата; открыть/переименовать/дублировать/удалить); новые файлы home-screen.component.tsx, project-card.component.tsx; modal-вариант с папкой удаляется.
- **top-bar**: домик слева вместо папки; ModeSwitch и Save удаляются (knip подчистит).
- **i18n**: ключи home.* / project.kind.* в en+ru.

## Этапы (через OpenSpec)
0. Change `add-project-home`: proposal + дельты specs project-library, persistence + tasks.
1. Модель данных и миграция хранилища (+ тесты).
2. Роутер + состояние: TanStack Router, view из URL, привязка проекта, autosave-в-проект, flush на pagehide.
3. App shell: рендер по роуту, топбар (домик; минус ModeSwitch/папка/Save).
4. Домашний экран: карточки, создание проекта с выбором типа.
5. Векторные проекты end-to-end + мост «Векторизовать».
6. Полировка: пустые состояния, legacy-миграция, i18n, design-review, PERFLOG.

Каждый шаг — полный фидбэк-луп (format → lint → arch:check → knip → tsc → test); после UI-шагов design-review. Тексты коммитов предлагаю после каждого изменения — коммитит человек.

## Риски
- Векторный проект ≈16 МБ в IndexedDB — приемлемо, запись троттлится.
- Ретрейс при открытии — сотни мс; смягчён мгновенным показом сохранённого SVG.
- projects-dialog в храповике — только новые файлы; удаление Save затрагивает хоткеи/топбар — шаг 3.
- SPA-fallback нужен на прод-хостинге (одна строка конфига).
