Процедурные генераторы — этап 1 (итеративно): композиционные ноды, корона, seed/🎲

Ключевое решение: НЕ строим параллельную систему «ProceduralGenerator» из документа — наш нодовый граф уже является «графом процедурных узлов» (их этап 5): параметры+seed сериализуются, рендер отделён, композиция (массивы, симметрия, intersect=clip) есть. Планируем ДОБАВЛЕНИЕ недостающего поверх графа. Лицо (landmark-модель) и L-система (пресеты+текст правил) — этап 2, следующим заходом.

## 1. Композиционные ноды (engine/nodes/repeats.node.ts / transforms.node.ts)
- **`mod.path` (Place along path)**: размещает накопленную карту входа count раз вдоль кривой. Параметры: `pathType` (line | arc | sine), `spanX/spanY` (вектор/размах), `count`, `rotateCopies` (bool — поворот копии по касательной), `scaleStart/scaleEnd` (линейная интерполяция размера копии), `jitter` 0..100 (seeded через withNodeRng), `seed`. Реализация в растровом пространстве: цикл по копиям, афинное преобразование клеток входа (как в arrayCircle, + масштаб), граница-клип.
- **`mod.scale` (Scale)**: масштабирует накопленную карту вокруг (cx, cy), sx/sy 0.1..4 — нужно для составных объектов (камни мельче зубцов).
Обе ноды — `kind: 'mod'`, работают с полным входом (мульти-составные объекты уже проходят через них).

## 2. `source.crown` — процедурная корона (новый файл engine/nodes/crown.node.ts, по образцу skull)
- Полилинии + fillCellsEvenOdd: лента-основание (rounded rect), зубцы по параметрической верхней кривой, камни-«кольца» (дырки) на зубцах.
- Параметры: width/height/x/y (span-разметка для канвас-лимитов), `spikes` 3..12, `spikeShape` select (triangle/diamond/rounded/gothic/double/notched), `spikeHeight/spikeWidth`, `jaggedness` (наклон/неровность зубцов), `asymmetry` 0..1 (правая половина деформируется, seeded), `jewels` 0..12 (дырки-кольца на зубцах/ленте), `jewelSize`, `bandHeight`, `seed`.
- Симметрия: генерируем левую половину профиля, отражаем, asymmetry сдвигает правую.
- Регистрация в index.ts + SHAPE_TOOL_PARAMS-подход не нужен (отдельная нода, не внутри source.shape).

## 3. Seed + 🎲 для всех новых генераторов
- У каждой новой ноды — int-параметр `seed`.
- **ObjectGraphPanel**: кнопка 🎲 «Пересоздать вариацию» — сканирует граф активного объекта, находит все числовые параметры с именем, содержащим `seed`, и проставляет случайные значения (одним undo-шагом через setObjectGraph). Работает и для bentoSeed у source.shape.

## 4. Пресеты-рецепты (engine/nodes/presets.ts)
- «Корона — классика» (source.crown + ramp + style), «Корона — с камнями» (jewels), «Корона — зигзаг» (spikeShape notched), «Шествие корон» (crown → mod.path → ramp) — демонстрация композиции. Каждый пресет = один объект (мульти-исходники уже объединяются в граф).

## 5. i18n + тесты + верификация
- Ключи `opt.crown*`, `opt.path*`, `mod.path`, `mod.scale`, `panel.reroll` (ru/en).
- Тесты: корона (силуэт в границах, детерминизм, число зубцов, дырки-камни), mod.path (кол-во копий, позиции по прямой/дуге), mod.scale (габариты), reroll-логика.
- Верификация: format → lint (0 ошибок; новые файлы ≤400/функция ≤150 — храповик) → arch:check → knip → tsc → 462+ теста → build → браузерный smoke (применить пресет «Корона», покрутить параметры, 🎲).

Этап 2 (следующий заход, зафиксировано): `source.face` (landmark-модель: контур головы, глаза-миндалины, зрачки, брови, нос, рот, асимметрия, выражение — по образцу skull), `source.lsystem` (аксиома/правила текстом + пресеты дерево/папоротник/коралл/молния, turtle→клетки), DSL-грамматика форм и PCA-вариации — этап 3, по мере надобности.
